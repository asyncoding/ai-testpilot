# 历史证据归档（archive）

本目录是 ai-testpilot 的**追加式历史台账**：核心文档（`docs/` 上层）只保留当前态的
最终结论、操作步骤与命令；所有带时间戳的历史证据——事故复盘、探针校准、方案演进与
废弃决策、真机验收台账、评测基线快照——统一归档于此，**只迁不毁、原文措辞保留**。

## 分层规则

1. 核心文档回答「现在怎么做、当前契约是什么」；本目录回答「为什么是现在这个结论、
   当时踩过什么坑、证据是什么」。
2. 核心文档需要历史背景处只留一行回链，例如
   `历史背景见 [INC-20261119-01](archive/01-事故与踩坑记录.md#inc-20261119-01)`
   （核心文档位于 `docs/` 下时的写法；本目录内互链省略 `archive/` 前缀）。
3. 条目**只追加、不删改**：结论被新证据修正时，原条目保留，新增条目并互相链接，
   带时间戳的日志/run-id/原始措辞不得回改（工程纪律：历史证据不篡改）。
4. 每条归档必须带来源锚点（源文档章节、run-id、commit、产物路径至少一项），
   使结论可回溯到一手证据。

- 日期取证据产生日（非归档整理日）；同日多条按 `-01/-02` 顺序编号。
- 证据只能定位到月份/批次而无具体日期的，ID 用可知的最粗粒度并在条目首行注明
  「具体日期未留存」，禁止编造精确日期。
- 每个条目前置显式锚点 `<a id="inc-..."></a>`，回链一律指向该 ASCII 锚点，
  不依赖中文标题自动生成的锚点。

## 条目模板

```markdown
<a id="inc-20261119-01"></a>
### INC-20261119-01 标题
- 日期/形态：（hermetic / 模拟器 / 真机）
- 现象：
- 根因：
- 处置：
- 预防/固化：
- 来源锚点：
```

CAL 增加「候选原型 → 实测事实 → 固化位置」；ADR 增加「被替代方案/状态」；
EVD 增加「run-id/证据指针/开放项」；BASE 增加「数据集口径/复跑命令」。
