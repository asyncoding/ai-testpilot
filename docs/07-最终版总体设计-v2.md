## 0. 建设策略：直接做最终架构，垂直切片交付

不做"手搓 RAG → 上框架 → 再重构"的线性学习路线，而是**第一天就按最终架构立骨架**，
每个里程碑交付一条可真实使用的纵切链路，在使用中暴露知识缺口，再在实现中定向补缺。

三条铁律：

1. **架构一次到位，范围逐片扩大**：端口/适配器、独立 runner worker、证据账本、HITL/outbox、
   评测/trace 从第一行代码就存在；不许先写死、后重构（单人项目"以后重构"≈永不重构）。
2. **每片都要真实使用 + 指标门禁**：每个里程碑结束必须有人（自己扮演测试/研发角色）真实使用，
   并跑通 [06](06-核心评测指标体系.md) 中该切片对应的指标门禁；指标不达标不进下一切片。
3. **知识按需补、补了留痕**：遇到不会的（LangGraph 状态机、FTS5、xcresulttool…）再学，
   学习结论沉淀进对应子系统的 ADR/注释，不另设"学习周"。

"最终版"的含义是**架构最终**，不是规模最终：多项目、K8s、Jira/GitLab 真实对接、vLLM 容量
均为 P2，留适配器接口和 profile，不在当前范围实现。

## 1. 设计原则（继承 v1.0 + 新增工程原则）

1. **迁就脏乱数据，不规范人**：以机器高可信信号（diff、CI、执行结果、commit 历史）为主，
   人写文本降权不删；知识沉淀是工作流副产物。
2. **无证据不结论**：所有事实性输出带引用、版本、新鲜度；检索为空/冲突显式降级为"未知"。
3. **核心不认识具体系统**：Core 只依赖端口接口与统一领域模型；xcodebuild/Gradle/Jira/文件路径
   一律在适配器层（[04](04-系统边界与外部对接清单.md) §6）。
4. **外部副作用最小授权 + 先账后事**：默认只读；写入必须 HITL，先持久化 outbox/幂等键再发起
   （[04](04-系统边界与外部对接清单.md) §7）。
5. **评测驱动**：每次 prompt/检索/模型改动都跑冻结 golden set，前后成对报告（[06](06-核心评测指标体系.md)）。
6. **环境差异诚实**：模拟器给不出的结论（真机后台、签名、多进程）显式标注未覆盖，不冒充已验。

## 2. 逻辑架构

```text
┌─────────────────────────────────────────────────────────────────┐
│ 触点通道（Channel Adapters）                                      │
│  Web 控制台（Next.js）  │  通知通道（P2：IM Bot/CI 评论）           │
└───────────────┬─────────────────────────────────────────────────┘
                │ REST / SSE
┌───────────────▼─────────────────────────────────────────────────┐
│ testpilot-orchestrator（FastAPI）                                 │
│  三条 LangGraph 工作流：问答 / 测试设计 / 执行归因                   │
│  统一模型 · 证据账本 · HITL 审批 · 权限策略 · outbox · 预算守卫     │
└───────┬──────────────────────────────────┬───────────────────────┘
        │ 端口接口（testpilot-core 定义）     │ 任务队列（QueuePort）
┌───────▼──────────────────────────────────▼───────────────────────┐
│ Workers                                                           │
│  ingest-worker（ETL/实体链接/索引/stale/reindex）                   │
│  runner-worker（独立进程执行测试，超时隔离）                         │
│  eval-worker（golden 回归 / RAGAS）                                 │
└───────┬──────────────────────────────────────────────────────────┘
        │ 适配器（按 profile 装配）
┌───────▼──────────────────────────────────────────────────────────┐
│ SCM(git) │ Docs(fs) │ Cases(md) │ Tickets(json) │ CI(json events)  │
│ Runner(xcode→P2:junit) │ Env(iOS sim→P2:k8s) │ Artifact(localfs)  │
│ Logs(os_log→P2:elk) │ Model(Ollama/云API) │ Vector(Chroma)        │
└──────────────────────────────────────────────────────────────────┘

数据底座：SQLite（元数据/FTS5 BM25/outbox/审批/评测/反馈）
          Chroma（向量）  │  本地 FS（制品/夹具）  │  Langfuse（trace）
```

与 [00](00-Demo总体设计-智能研发测试助手.md) v1.0 的差异：

- CI、测试执行器、环境管理器明确为三个独立外部系统，runner 从第一天独立进程化；
- 知识库拆为**知识源（端口）**与**派生索引（TestPilot 资产）**，文件系统只是源适配器；
- 评测/trace/outbox 不是第 9 个模块，而是横切所有工作流的内建能力。

## 3. 子系统与代码边界

工程容器根：`subsystems/`，分包即边界，Core 的 import 规则用 lint 强制
（禁止 core 依赖任何 adapter / SDK）。

| 子系统 | 职责 | 关键内容 |
|---|---|---|
| `testpilot-core` | 领域模型、端口接口、策略、证据账本模型、错误/降级类型 | 无 IO、无 SDK、无框架依赖（纯 Python） |
| `testpilot-orchestrator` | FastAPI、LangGraph 三图、HITL API、outbox 调度、SSE | 只依赖 core 的端口 |
| `testpilot-worker-ingest` | 连接器拉取 → 归一化 → 质量评分 → 实体链接 → 切块嵌入 → 登记元数据；stale/reindex | ETL 每步留痕 |
| `testpilot-worker-runner` | 接收 TestExecutionRequest，调 runner adapter，采制品，超时/取消隔离 | 独立进程，**LangGraph 节点不直接 subprocess** |
| `testpilot-worker-eval` | golden set 离线评测、RAGAS/规则裁判、报告产出 | 题集与语料隔离校验 |
| `adapters/*` | git / fs-docs / md-cases / json-tickets / json-ci-events / xcode-runner / ios-sim-env / localfs-artifact / oslog-logs / chroma-vector / fts5-bm25 / ollama-model / cloud-model(P1) / junit-runner(P2) | 每个 adapter 一个目录 + 契约测试 |
| `testpilot-web` | Next.js 控制台：对话页、用例审批页、执行/归因详情、知识与 stale 管理、评测看板 | 调 orchestrator REST/SSE |
| `deploy/` | docker-compose（dev/ios-local-poc/offline-demo profile）、Ollama、Langfuse、Redis、Chroma 编排 | 一键起 |
| `fixtures/` | 工单 JSON、CI 事件 JSON、离线 runner 录制结果、golden set | 生成物不入库 |

进程间通信：

- orchestrator → workers：`QueuePort`，默认 Redis（RQ/arq 类轻量实现）；
  offline profile 用 SQLite 队列表，保证无外部依赖也能演示完整状态机；
- worker → orchestrator：回写 SQLite 业务库 + 任务状态；前端经 SSE 订阅进度；
- 所有跨进程任务带 `idempotency_key`，worker 至少一次投递 + 任务侧幂等。

## 4. 统一领域模型（testpilot-core）

首批必须落定的模型（字段全量在需求说明书 [08](08-需求说明书.md) 中展开）：

```text
Project/RepoRef          项目与仓库引用（路径走配置，不写死）
SourceDocument           知识源文档（source_system, uri, version/etag, acl, 权威等级）
KnowledgeChunk/Entity/Relation   切块、实体、带 confidence+证据的关系
Requirement/TestPoint/TestCase    需求、测试点、结构化用例{前置,步骤[],oracle[]}
ChangeSet/CodeSymbol     diff 变更集、版本化符号（稳定 SymbolId，不绑行号）
TestExecutionRequest/TestRun/CaseResult    语言中立的执行契约
Issue/IssueDraft         工单与工单草稿
Evidence/EvidenceRef     证据（source_system, uri, version/hash, 查询条件, 抓取身份, 时间）
Approval/OutboxRecord    人审记录、外部副作用账本
Feedback                 采纳/修改/拒绝 + 原因
EvalCase/EvalRun         golden 题与评测批次（数据/模型/prompt/参数版本四元组）
```

URN 规范：`urn:testpilot:<source_system>:<resource_type>:<external_id>@<version>`。

## 5. 三条工作流（最终形态）

### 5.1 知识问答图

```text
提问 → 意图/权限校验 → 混合检索(FTS5+Chroma+rerank) → 证据分级
     → 代码类问题强制 live-verify(HEAD 符号/hash 复核)
     → 生成（带引用骨架，约束只许引用召回证据）
     → 引用校验器（URI 可达/hash/版本；失败则重生成或降级"未知"）
     → 输出（答案+引用+版本+新鲜度标注；历史证词并列"历史经验/当前实现"）
     → 反馈采集
```

### 5.2 测试设计图

```text
需求接入 → 骨架抽取{功能点,规则,验收标准,模块}（缺验收标准显式标缺）
        → 影响面检索（相似历史用例/事故/相关符号）
        → 测试点生成 → 用例生成（结构化；oracle 四类：UI/日志/状态/人工）
        → oracle 挖掘（需求验收标准/现有断言/历史缺陷/当前代码 四源）
        → 草稿（不入库）→ HITL（采纳/修改/拒绝；diff 即偏好样本）
        → 批准后经 TestCaseRepositoryPort 回写（Markdown adapter 起步）
```

### 5.3 测试执行与失败归因图

```text
选择用例/接收 PipelineFinished 事件
  → 环境能力校验（模拟器不满足真机能力直接 unsupported_capability）
  → EnvironmentPort.acquire → runner-worker 执行（xcodebuild；P2 JUnit）
  → 采集 xcresult/JUnit + 截图/录屏 + os_log（按 runId/时间窗）
  → 失败归因（候选：真缺陷/用例过期/flaky/环境失败/产品改动；先列多候选再取证区分）
  → 归因结论 + 证据包 + 置信度
  → HITL → outbox：MR 评论 / 工单草稿 / 用例更新建议（R2/R3 分级，见 04 §7）
```

### 5.4 横切能力（每个节点都经过）

- **证据账本**：每次工具调用与结论写 Evidence，可从输出反查全部来源；
- **预算守卫**：步数/token/重跑次数硬上限；工具白名单；
- **trace**：全链路 Langfuse（runId 与证据账本、TestRun 关联）；
- **降级标注**：模型/检索/适配器任一不可用时输出降级标记，计入评测。

## 6. 知识工程与保鲜（继承 v1.0 §3–4，工程化落地）

- 四层：L0 实时联邦（代码/CI/工单状态不缓存结论）、L1 实体关系（SQLite）、
  L2 混合索引（Chroma + SQLite FTS5）、L3 规则资产（术语表/prompt/golden/few-shot）。
- 加工管线：解析归一化 → 质量评分 → 实体链接 → 切块嵌入 → 元数据登记，**每步产出可在
  Web "知识管理"页查看**（切块样本、关系 confidence、质量分）。
- 保鲜：事件驱动（CommitPushed/PipelineFinished/…，事件 schema 见 04 §8）+ 定时全量兜底；
  摄入延迟 P95 <5min；符号锚定不绑行号；重构→STALE→高价值立即 reindex/低价值 lazy；
  事故文档不改写，只加"验证于版本 X"；分支双轨 namespace（P1）。

## 7. 评测与可观测（内建，不是外挂）

- golden set：30 题起步（S1 门禁），S5 扩到 ~100 题，配比与负例规则按 [06](06-核心评测指标体系.md) §6；
  专家盲标（POC 期自己扮演专家，但流程保留"先独立列点再看 AI"）。
- eval-worker 每次变更产出评测报告（数据/模型/prompt/参数版本四元组标注）；
  指标集按 [06](06-核心评测指标体系.md) §7 的 POC 最小 10 指标采集，Web 看板展示趋势。
- Langfuse 记录延迟/token/工具调用；成本与 golden 通过率成对报告。
- 三个护栏指标（无引用结论=0、越权=0、严重误导=0）在 CI/评测中机器校验。

## 8. 安全、权限与审计

- POC 单用户 dev 身份 + 配置化 ACL 雏形；端口预留 `AccessScope`，适配器侧过滤；
- 密钥走环境变量/`.env`（不入库），端口预留 Secret 管理；
- 所有外部写操作：Approval + OutboxRecord（请求体/幂等键/目标系统/回滚说明）+ 对账任务；
- 数据本地处理，模型默认 Ollama 本地；云端 API 仅在显式配置且数据分级允许时可用。

## 10. 里程碑（垂直切片，替代 01 的周计划）

每片都含：可运行链路 + 真实使用 + 指标门禁 + ADR。顺序即依赖顺序，但每片结束系统都是完整的。

### S0 骨架与契约（约 3–5 个工作日）

- 子系统骨架、core 模型与全部端口接口、配置/profile 加载、docker-compose 能起空架；
- SQLite 表结构（元数据/outbox/审批/反馈/评测）、FTS5、Chroma、Redis、Langfuse 连通；
- adapter 契约测试骨架（用录制夹具，不依赖真机/模拟器）；
- **门禁**：core import  lint 通过；契约测试在 CI 绿；空链路 trace 出现在 Langfuse。

### S1 知识问答纵切（首个可用产品）

- git + 文件文档适配器；ETL（Markdown/代码 AST 切块先做 SwiftSyntax 最简符号切）；
- FTS5+Chroma 混合检索；问答图全节点（含 live-verify、引用校验、"未知"降级）；
- Web 对话页；30 题 golden（含负例）+ eval-worker + 看板雏形；
- **门禁（06 §3.1/§7）**：引用准确率 ≥0.95 且伪造引用=0；Recall@K ≥0.85；
  负例拒答正确率 ≥0.9；忠实度 ≥0.9；trace 覆盖率 100%。

### S2 测试设计纵切

- 用例 Markdown 适配器、需求抽取、测试点/用例生成、oracle 四源挖掘、审批页、回写；
- 5 个真实需求盲标评测；采纳 diff 回流 L3；
- **门禁**：测试点覆盖率 ≥0.75、P0/P1 漏点=0、幻觉点率 ≤0.05、oracle 有效率 ≥0.7、
  结构合法率 100%。

### S3 执行与失败归因纵切（最重）

- runner-worker + xcode adapter（先 hostless，再单条 XCUITest）、simctl env、
  xcresulttool 解析、os_log 查询、artifact 存储；CI JSON 事件适配器；
  归因图（含 flaky 重跑验证、用例过期对照证据）；JSON 工单适配器 + outbox 写回（dry-run→HITL）；
- **门禁**：执行成功率 ≥0.95；归因准确率 ≥0.7 且**真缺陷 recall ≥0.95、误误导率 ≤0.02**；
  证据充分率 ≥0.9；幂等正确性 100%；重跑预算遵守 100%。
- 必须做对照实验：临时回退修复/断言，验证归因与测试能抓住（06 §6.3）。

### S4 保鲜、影响面与事件纵切

- 事件 JSON 可 replay；现场重构 stale→reindex 演示；MR 摘要与影响用例推荐；
  定时全量兜底；知识管理页（权威等级/质量分/stale 列表/知识 owner 字段）；
- **门禁**：摄入延迟 P95 <5min；未标 stale 过期命中≈0；高价值 reindex <10min；
  影响推荐精度 ≥0.8。

### S5 治理、私有化与第二技术栈验证

- golden 扩至 ~100；全量看板（06 全部指标）；bad case 分诊台账；Ollama 全链路切换验证；
  offline-demo profile 完整走查；**JUnit Surefire XML adapter 契约验证**（证明 TestRun 语言中立）；
  模型路由/缓存的成本前后对比；一键 runbook；
- **门禁**：三护栏全 0；周有效采纳率（自演示用法统计）≥50%；成本报告成对数字齐全。

### P2（当前不实现，只留接口）

分支双轨索引、真实 GitLab/Jira/Jenkins/设备云对接、K8s 环境适配器、IM Bot、
vLLM 容量实测、多项目/权限体系。

## 11. 技术选型（最小必要集）

| 用途 | 选型 | 备注 |
|---|---|---|
| 语言/API | Python 3.12 + FastAPI + Pydantic | 端口与模型在 core，FastAPI 仅在 orchestrator |
| 编排 | LangGraph | 状态持久化用 SQLite checkpointer；步数预算/HITL interrupt |

| 可观测 | Langfuse 自托管 + 结构化日志（固定 logger 名） | 关键链路日志谓词写进 runbook |
| Web | Next.js（App Router）最小控制台 | 对话/审批/执行详情/知识/看板五页 |
| iOS 侧 | xcodebuild / xcresulttool / simctl / SwiftSyntax（摄入侧 AST） | 命令见 [03](03-语料工程与实测环境（AlarmKitSpike）.md) |
| 评测 | RAGAS + 自研结构化断言 | 裁判模型与生成模型隔离 |
