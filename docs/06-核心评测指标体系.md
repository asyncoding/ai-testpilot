| 项 | 内容 |
|---|---|
| 版本 | v0.1（2026-11-01 讨论稿） |
| 目的 | 把"系统好不好"拆成可计算、可归因、可回归的指标；明确每个指标怎么算、数据从哪来、POC 目标值 |
| 配套 | 场景与模块见 [00](00-Demo总体设计-智能研发测试助手.md)；角色与阶段准出见 [05](05-角色协作与落地推进手册.md)；trace/成本基建见 [13-系统使用说明书（克隆到演示全流程）.md](13-系统使用说明书（克隆到演示全流程）.md) 外部服务章节 |
| 原则 | **先定怎么算，再定目标值；先测基线，再谈提升；每个 AI 质量数字标注数据版本/模型版本/参数版本** |

## 1. 指标体系总图

非确定性系统不能只看"演示效果"，要同时回答四个问题：**有没有人用（采纳）、输出对不对（质量）、
错了能不能控（安全/降级）、贵不贵快不快（成本/性能）**。

```text
L0 业务价值层     用户与业务结果：定界耗时、用例编写耗时、采纳率、周活、漏测
     ↑ 由
L1 场景质量层     ① 知识问答 ② 测试设计 ③ 执行归因——每场景独立指标
     ↑ 由
L2 系统能力层     检索召回、引用准确、live-verify、stale 率、Agent 完成率/越权率
     ↑ 由
L3 平台基座层     延迟、错误率、token 成本、GPU 利用率、trace 覆盖、golden 回归通过率
     ↑ 护栏贯穿所有层：幻觉零容忍类、安全审计、数据出域 0 事件
```

**北极星指标（试点期只认一个）**：**周有效采纳率**——每周由用户明确采纳（用例入库、
归因被确认、答案点"有用"）的 AI 输出占总输出的比例，按场景分别统计。

三个护栏指标（任何一个越线，北极星数字再好也要暂停扩量）：

1. **无引用结论率 = 0**（所有事实性回答必须有证据引用；例外：纯方法论闲聊，需白名单标记）；
2. **越权读写事件 = 0**；
3. **用户标记"严重误导"的输出 = 0**（指可能导致错误发布或误判缺陷的结论，区别于"不好用"）。

## 2. L0 业务价值指标（对管理层讲的数字）

| 指标 | 定义/算法 | 数据源 | POC/试点目标建议 |
|---|---|---|---|
| 周有效采纳率 ★ | 周内被明确采纳的输出数 / AI 总输出数（分场景） | HITL 审批表 + 反馈按钮 + 回写记录 | POC ≥50%，试点 ≥60% |
| **失败定界耗时**（场景③） | CI 失败到人工确认归因类别的中位时长；对比 AI 辅助前后 | CI 时间戳 + 归因确认时间 | 基线对比下降 ≥40% |
| **用例编写耗时**（场景②） | 从需求可读至用例草稿过审的中位时长 | 用例平台版本时间戳 | 基线对比下降 ≥30% |
| 知识自助解决率（场景①） | 提问后 10 分钟内未转人工询问的会话占比（IM 场景） | IM 会话 + 转人工信号 | ≥70% |
| 周活跃用户率 WAU% | 每周至少 3 次有效使用的用户 / 试点组人数 | 访问日志 | 试点组 ≥60%（docs/05 准出） |
| 回归选择有效率 | AI 影响面推荐且实际执行的用例中，确实与变更相关的比例；兼看**回归集缩减比例** | 用例执行记录 + 缺陷命中 | 推荐精度 ≥80%，回归条数可讲缩减% |
| 缺陷漏测变化 | 试点模块上线后逃逸缺陷率对比（前后周期，样本小需谨慎） | 工单系统 | 只观察不下硬指标，至少不恶化 |
| 人力释放叙事 | 用样本工时法：n 个真实任务的 AI 辅助 vs 纯人工耗时 | 抽样实测（≥20 任务） | 用于 ROI 陈述，不做平台 KPI |

注意：采纳率要防"一键采纳刷分"——同时看**采纳后 7 天撤销/修改率**（虚高信号）和
**修改 diff 幅度**（原样采纳 vs 大改后采纳，加权区分）。

## 3. L1 场景质量指标

### 3.1 场景① 知识问答（RAG）

| 指标 | 定义 | 怎么算 | 目标建议 |
|---|---|---|---|
| **答案忠实度** Faithfulness | 答案中能被检索上下文支撑的陈述占比 | RAGAS 忠实度（LLM 裁判 + 抽检人工） | ≥0.9 |
| **答案相关性** Answer Relevance | 答案对问题的切题程度（不跑题、不套话） | RAGAS answer relevancy | ≥0.85 |
| **上下文命中率** Context Recall | 标准答案所需证据片段被召回的比例 | golden 标注的必需证据 vs 实际召回 | ≥0.85（Top-K 全集） |
| **上下文精确率** Context Precision | 召回片段中相关片段的比例与排序质量 | RAGAS context precision | ≥0.7 |
| **引用准确率** ★ | 答案中每个引用经核验真实存在、内容支撑陈述、版本正确的比例 | 自动：URI 可达+hash 校验；人工抽检语义支撑 | ≥0.95，**伪造引用 = 0** |
| live-verify 拦截率 | 生成前发现引用符号在 HEAD 已变更并当场重读的次数/应校验次数 | 工具调用日志 | 覆盖率 100%（代码类问题强制）；另统计拦截后避免错误答案数 |
| 版本/新鲜度标注正确率 | 答案上的"一致✅/验证于版本 X/未知"标注与实际相符比例 | 离线构造过期样本测试 | ≥0.95 |
| **"未知"正确率** | 该拒答时拒答的比例（召回为空/冲突时的降级质量） | 构造无答案题库（NQ 式负例） | 拒答正确率 ≥0.9；**乱答率 ≈0** |
| 历史证词区分正确率 | 事故复盘类问题是否正确并列"历史经验 vs 当前实现" | 专项题集人工评 | ≥0.9 |

RAG 故障归因用二分法：**答案错时分清是召回问题还是生成问题**——
若上下文中根本没有正确证据 → 检索侧（调切块/混合检索/rerank）；上下文有正确证据但答案错
→ 生成侧（调 prompt/模型/引用约束）。每次 bad case 必须打上这个标签，周会统计两侧占比。

### 3.2 场景② 测试设计 Agent（需求→测试点→用例）

| 指标 | 定义 | 怎么算 | 目标建议 |
|---|---|---|---|
| **测试点覆盖率（召回）** ★ | AI 测试点覆盖专家认定"必须测"测试点的比例 | 专家对 N 个真实需求先独立列点，再比对 | POC ≥0.75，试点 ≥0.85 |
| 测试点精确率 | AI 输出点中专家认可为有效的比例（防灌水凑数） | 同上反向 | ≥0.8 |
| 漏点率 | 专家有、AI 没有的关键点比例（=1−覆盖率，单独强调因为最危险） | 同上 | ≤0.15 且无 P0/P1 级漏点 |
| 幻觉点率 | 引用了不存在的需求条目/符号/接口的测试点比例 | 需求版本 + 代码 live-verify | ≤0.05，**P0 幻觉 = 0** |
| **oracle 有效率** ★ | 挖出的 oracle 被专家判为"可执行且正确"的比例；分类统计 UI/日志/状态/人工四类 | 专家评审 3.3 节的草稿 | ≥0.7 |
| oracle 挖掘覆盖率 | 原本无预期的存量用例中，成功补出至少一条可执行 oracle 的比例 | 用例库前后 diff | ≥60%（剩余标探索性用例是正常出口） |
| 用例草稿采纳率 | 原样/小改/大改/拒绝四档分布 | HITL 审批记录 | 原样+小改 ≥60% |
| 单需求生成成本 | 每需求平均 token 成本与延迟 | Langfuse | 记录趋势（路由后应下降） |
| 结构合法率 | 输出符合结构化 schema（前置/步骤/oracle 分类齐全）比例 | 解析器 | 100%（structured output 兜底） |

**关键评测设计**：专家必须**在看到 AI 输出之前**独立写测试点（盲标），否则会被 AI 清单锚定，
覆盖率虚高。漏点率比采纳率更能说明系统边界——试点要主动暴露它。

### 3.3 场景③ 测试执行与失败归因

| 指标 | 定义 | 怎么算 | 目标建议 |
|---|---|---|---|
| **归因准确率** ★ | 归因类别（真缺陷/用例过期/flaky/环境/产品改动）与人工最终结论一致的比例 | 以历史已知失败+试点期人工确认为 ground truth | POC ≥0.7，试点 ≥0.85 |
| 分类混淆矩阵 | 各类别的 precision/recall，尤其"真缺陷"不能漏报 | 标注集 | 真缺陷 recall ≥0.95（漏报代价最高） |
| 证据充分率 | 归因附带的日志/代码/制品证据足以让第三人复核结论的比例 | 人工抽检 | ≥0.9 |
| **误误导率** | 把真缺陷判成 flaky/用例问题等可能放过缺陷的错误比例 | 混淆矩阵派生 | ≤0.02，护栏级 |
| flaky 判定质量 | 判 flaky 后重跑结果的实际通过率（验证 flaky 判断） | runner 重跑记录 | 判 flaky 的用例重跑通过率 ≥0.9 |
| 定界耗时 | 见 L0 | — | 下降 ≥40% |
| 执行成功率 | runner 任务本身成功产出结构化 TestRun 的比例（基础设施稳定性，非用例通过率） | TestRun.status | ≥0.95；error/timeout 单列 |
| 环境适配正确率 | 模拟器能做/不能做的结论是否正确标注（不声称验过真机行为） | 专项构造 | 越层声称 = 0（工程纪律） |
| 重跑预算遵守率 | Agent 触发重跑次数/时长不超日配额的比例 | 预算账本 | 100% |
| 端到端闭环完成率 | 失败→取证→归因→草稿→人审→回写 全流程无人工兜底完成的比例 | run 状态机 | POC ≥0.6，试点 ≥0.85 |

归因 ground truth 建设：用 AlarmKitSpike 真实历史（用例期望 90s→30s 过期、授权竞态、
模拟器不暴露真机行为、flaky）做标注集；上线后以人工确认结论持续回流。
**对照实验纪律**：新归因规则上线前，在历史失败集上回测，必要时临时回退修复验证测试能变红
（CLAUDE.md 工程纪律的迁移）。

## 4. L2 检索与知识保鲜指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 检索召回 Recall@K | golden 查询的必需证据进入 Top-K 的比例 | ≥0.85 |
| MRR / NDCG@5 | 相关证据的排序质量 | MRR ≥0.7 |
| 混合检索增益 | 向量 only → BM25+向量+rerank 各阶段命中率变化 | 每阶段记录，作为调参证据 |
| 代码 AST 切块 vs 文本切块 | 同一批代码类问题的命中率对比 | 用数据回答切块策略题 |
| 摄入延迟 P95 | 事件发生（push/CI finished）到可检索的时间 | 目标 <5 分钟（docs/00 §4.1） |
| **stale 命中率** ★ | 检索结果中已过期（符号重构/文档失效）但未被标记的比例；用现场重构演示实测 | 未标 stale 命中 ≈0；标记及时率 ≥0.95 |
| reindex SLA | 高价值条目变 stale 后完成 reindex 的时长；低价值 lazy 命中时再生时长 | 高价值 <10 分钟 |
| 实体链接准确率 | L1 抽取的实体关系（用例↔符号、缺陷↔commit）经抽检正确的比例；另看 confidence 校准度 | ≥0.85；低置信降权是否合理要验证 |
| 蓝色双轨切换正确率 | 分支提问是否路由到正确 namespace；重构分支预索引是否在合入前完成 | 专项演示，100% |
| 质量分排序有效性 | 高质量条目实际排在前面的程度（用点击/采纳后验校准 quality_score） | 季度做一次校准分析 |

## 5. L3 Agent 工程化、成本与平台指标

### 5.1 Agent 可控性

| 指标 | 定义 | 目标 |
|---|---|---|
| 任务完成率 | 在步数/时间预算内正常结束（非 abort/超限）的任务比例 | ≥0.95 |
| 平均工具调用步数 / token 预算超限率 | 可控性与成本的双重观察 | 超限率 <2% |
| 循环/失控拦截率 | 状态机守卫实际拦住重复调用/越权工具的次数 | 白名单外调用 = 0 |
| 幂等正确性 | R2/R3 写操作重试后无重复工单/重复评论的比例（docs/04 §7） | 100%；对账幻影记录清零 |
| HITL 拦截有效率 | 人审拒绝的草稿中，事后确认"幸亏没发"的比例（抽样） | 证明人审节点价值 |
| 人审平均耗时 | 草稿到审批动作的中位时间（人审不能成为瓶颈） | <2h（工作时段） |

### 5.2 成本与性能

| 指标 | 定义 | 备注/目标 |
|---|---|---|
| 单场景请求成本 | 平均/分位 token 成本（输入/输出/embedding 分列），标注模型版本 | 路由+缓存前后对比是核心叙事 |
| 模型路由命中率 | 小模型可搞定的请求被正确分流的比例；及小模型升级大模型的 escalate 率 | 给出成本下降%（如 ≥40%） |
| 缓存命中率 | 精确+语义缓存命中比例，及命中后质量抽检不降质 | 记录 |
| 首 token / 端到端延迟 P50/P95 | 分场景 | 问答 P95 <8s 为体感及格线（POC 本地模型可放宽，如实写） |
| 有效 QPS / GPU 利用率 | 私有化部署容量口径；2×A100 场景 | Week 5 补容量测算文档 |
| 服务可用性 / 错误率 | 5xx、超时、模型网关降级触发次数 | 降级路径必须显式标注并计入评测 |

### 5.3 评测过程与治理指标（元指标）

| 指标 | 定义 |
|---|---|
| golden set 规模与覆盖 | 题量、场景/难度/负例分布；POC 30–50 题，试点 ~100 题 |
| golden 回归通过率 | 每次 prompt/模型/检索改动后冻结题集的通过率曲线（演示第 6 步的主曲线） |
| 评测题泄漏率 | 入库语料与题集的重合检查（留出事故事件不入库、不进 few-shot） |
| trace 覆盖率 | Langfuse 可完整追溯的请求比例（输入/检索/工具/输出/成本齐全） |
| bad case 闭环周期 | bad case 从发现到修复回归通过的中位时长；周会分诊（docs/05 §8） |
| 反馈率 | 用户输出中获得明确反馈（采纳/修改/拒绝+原因）的比例；反馈是在线真值来源 |
| 数据/模型/参数版本标注完整率 | 每个评测结果三元组标注齐全的比例 |

## 6. 评测方法与 golden set 设计

### 6.1 离线评测（每次改动必跑）

1. **题集冻结、版本隔离**：golden set 由领域专家主标（docs/05 RACI），事故文集中留 10–20 篇
   不入库做留出问答集；题集进 git 版本管理，改题要走评审。
2. **题集结构**（100 题参考配比）：

| 类型 | 占比 | 作用 |
|---|---|---|
| 事实型问答（有据可查） | 30% | 忠实度/引用准确率 |
| 代码机制深问（需 live-verify） | 15% | 实时校验、AST 切块 |
| 历史 vs 当前对比题 | 10% | 版本区分、事故证词 |
| **无答案/越权负例题** | 15% | 测"未知"降级，防乱答 |
| 需求→测试点/用例 | 15% | 覆盖率/漏点/oracle |
| 失败归因案例（带真实历史标签） | 15% | 归因准确率/误误导率 |

3. **裁判方式分层**：结构化断言（引用 URI/hash、schema 合法、分类标签）全自动；
   语义类用 LLM-as-judge 但**每个题保留人工裁定入口**，裁判模型与生成模型不得同体自评，
   按 ≥10% 比例人工抽检裁判一致性（kappa）。
4. **改动前后对照**：任何调优提交必须附 golden 前后对比，禁止只报升分不报降分；
   评测报告标注数据版本/模型版本/prompt 版本/参数版本/是否降级路径。

### 6.2 在线评测（试点期）

- 隐式信号：采纳/修改 diff/撤销、引用点击、重问率（一次没答对再换问法）、转人工率；
- 显式信号：👍👎 + 原因分类（没召回/引用过期/答非所问/事实错）；
- 真人轮值抽查：专家前两周每天抽 5 条（docs/05 场景 A）；
- 影子模式（写入类动作上线前）：AI 出归因/工单草稿但不回写，与人工实际结论比对，
  统计一致率后再申请写权限。

### 6.3 必须能演示的"反假绿"实验

1. **回退修复看测试变红**：新归因规则/测试在回退修复时确实失败（对照实验，CLAUDE.md 纪律）；
2. **现场制造过期**：重命名符号后 stale 标记与答案更新全过程；
3. **负例拒答**：问一个语料中不存在的东西，系统答"未知"而不是编；
4. **版本错配陷阱题**：用 90s 旧常量问当前实现，答案必须给 30s 当前值并标注历史值。

## 7. POC 最小指标集（别一上来铺 40 个指标）

四周内只建这 10 个，每个都有自动采集路径：

| # | 指标 | 采集方式 |
|---|---|---|
| 1 | golden 回归通过率（冻结 30 题） | 离线评测脚本 |
| 2 | 引用准确率（含伪造引用 = 0） | URI/hash 自动 + 人工抽 20% |
| 3 | 上下文命中率 Recall@K | golden 标注 |
| 4 | 忠实度 | RAGAS + 抽检 |
| 5 | 无答案题拒答正确率 | 负例题集 |
| 6 | 测试点覆盖率/漏点率 | 专家盲标 5 个需求 |
| 7 | 归因准确率 + 真缺陷 recall | 历史失败标注集 |
| 8 | 周有效采纳率 + 采纳后撤销率 | HITL/反馈表 |
| 9 | 单请求成本与延迟（路由前后） | Langfuse |
| 10 | 摄入延迟 P95 + stale 演示案例 | 事件日志 |

试点期再补齐 L0 价值指标与在线反馈体系。**没有基线的指标不进汇报**——立项期测的
基线值（docs/05 阶段 0）是所有"下降/提升 %"的分母。

## 8. 虚荣指标与常见作弊（评审常见追问）

| 反模式 | 问题 | 正确做法 |
|---|---|---|
| 只看"回答满意度"主观分 | 锚定宽松、不可复现 | 以引用准确/忠实度等可客观核验指标为主 |
| 用入库语料做题集 | 循环引用刷分 | 留出隔离 + 泄漏检查 |
| 只演示准备好的问题 | 表演赛 | dogfood 真实问题 + 专家超纲出题 |
| 采纳率高但撤销率不看 | 一键采纳虚高 | 采纳后 7 天撤销/修改联动统计 |
| 平均成本下降但不报质量变化 | 缓存/小模型可能降质 | 成本与 golden 通过率成对报告 |
| 归因准确率高但不报混淆矩阵 | 真缺陷被漏报会被平均值掩盖 | 分类报告 + 真缺陷 recall 护栏 |
| 全绿单次运行 | 假阳性（断言错/匹配同名节点） | 回退实验 + 抽帧/录屏取证（UI 场景） |
| 报"智能化率 xx%" | 不可计算 | 只报可复算定义的指标 |
