## A. 缩写与英文缩略

| 术语 | 全称 | 一句话人话 | 本项目具体所指 |
|---|---|---|---|
| FR | Functional Requirement | 功能需求：系统必须能做的事 | 编号 `FR-<域>-<号>`，如 FR-CON-003，见 [08](08-需求说明书.md) |
| NFR | Non-Functional Requirement | 非功能需求：不是"做什么"而是"做得怎么样"（性能、安全、可移植……） | NFR-001~009，[08](08-需求说明书.md) §12 汇总表 |
| AC | Acceptance Criteria | 验收标准：这条需求做到什么程度算合格 | 每条 FR 下的 AC1/AC2……，Given/When/Then 风格从简写 |
| SRS | Software Requirements Specification | 需求规格说明书 | 即 [08-需求说明书.md](08-需求说明书.md) |
| P0/P1/P2 | Priority | 优先级：P0 该里程碑必须做，P1 S5 前必须，P2 只留接口不实现 | [08](08-需求说明书.md) 头部优先级说明 |
| URN | Uniform Resource Name | 统一资源名：给每个外部资源发一个系统内身份证号，外部系统自己的 ID 不当主键 | 格式 `urn:testpilot:<system>:<type>:<id>@<version>`（[07](07-最终版总体设计-v2.md) §4） |
| HITL | Human-In-The-Loop | 人在回路：关键动作（尤其外部写入）机器只准备草稿，人点头才执行 | 审批队列/审批页，FR-WR-001 |
| ACL | Access Control List | 访问控制名单：谁能看什么 | SourceDocument 的 acl/密级字段，检索时按 AccessScope 过滤 |
| AST | Abstract Syntax Tree | 抽象语法树：把源码解析成树状结构，按类/函数精确切块而不是按行数切 | FR-ING-002；Python 侧实际用零依赖词法扫描器，tree-sitter 为可选 adapters 方案 |
| FTS5 | Full-Text Search 5 | SQLite 自带的全文检索引擎，不用额外装 ES 之类组件 | BM25 检索通道，与 Chroma 向量通道融合 |
| BM25 | Best Matching 25 | 经典关键词检索打分算法：词越稀有、命中越多排名越高 | FTS5 内置；注意它输出的是排名量级不是百分制质量分 |
| RRF | Reciprocal Rank Fusion | 倒数排名融合：多路检索各出一份排名，按名次（不看原始分）合成一份 | 三通道混合检索的融合公式 |
| RAG | Retrieval-Augmented Generation | 检索增强生成：先查资料再让模型照着资料回答，不许裸答 | 知识问答图（[07](07-最终版总体设计-v2.md) §5.1） |
| RAGAS | RAG Assessment | 一套 RAG 评测框架/指标集（忠实度、答案相关性等） | eval-worker 语义裁判，裁判模型与生成模型不同体 |
| ETL | Extract Transform Load | 抽取-转换-加载：把外部数据搬进来、洗干净、存好的流水线 | ingest-worker 加工管线，每步留痕 |
| CI | Continuous Integration | 持续集成：push 后自动构建/跑测试的流水线 | PipelineFinished 事件、CI JSON 事件适配器 |
| MR | Merge Request | 合并请求（GitLab 叫法，GitHub 叫 PR） | R2 级外部写：MR 评论默认走审批 |
| SSE | Server-Sent Events | 服务器单向推送消息的网页技术 | 前端订阅 worker 进度（POC 期流式未授权不做） |
| LLM | Large Language Model | 大语言模型 | 默认本地 Ollama（qwen2.5:7b 等），云端 API 显式开关 |
| P95 | 95th Percentile | 95 分位：100 次请求里最慢的 5 次之外的门槛值，比平均值抗极值 | NFR-003 问答 P95 <8s、摄入 P95 <5min |
| Recall@K | — | 召回率@K：前 K 条结果里包含正确答案的比例 | S1 门禁 Recall@K ≥0.85 |
| udid | Unique Device Identifier | 苹果设备/模拟器的唯一标识码 | 设备清单走 profile 注入（禁止写死）；运行期由环境租约 `env_id_for_lease` 解析后经 request labels 透传给 runner |
| scheme | — | Xcode 工程的构建方案名（决定跑哪个 target/配置） | 同上，配置注入 |
| xcresult | — | Xcode 测试跑完产出的结果包（含用例结果、失败信息、附件） | xcresulttool 解析，离线时用录制件 |
| xcodebuild / simctl | — | 苹果命令行：前者构建跑测试，后者管模拟器 | runner/环境适配器调用，core 里 grep 不到（防腐红线） |
| os_log | — | 苹果统一日志系统（App 与系统日志） | LogQueryPort 按 runId/时间窗/谓词查询 |
| XCUITest | — | 苹果 UI 自动化测试框架 | S3 单条选择执行；hostless 套件先行 |
| SwiftSyntax | — | Swift 官方语法树库（Swift 侧） | 仅作选型背景；Python 入库管不了它，见 FR-ING-002 实现注记 |

## B. 工程借词（行业黑话 → 人话）

| 术语（英文） | 一句话人话 | 本项目具体所指 |
|---|---|---|
| 端口（Port） | 核心层开出的"能力欠条"：只定义要什么接口，不关心谁来实现 | `testpilot-core` 里的 Protocol，如 CodeRepositoryPort、ModelGatewayPort |
| 适配器（Adapter） | 端口的具体交工方：把某个真实外部系统接到接口上 | `packages/adapters/`，每个端口有真实 + 离线录制两种实现可切 |
| 契约测试 | 不看内部实现，只验"给定输入必须产出约定输出"的测试 | 每个 adapter 一份，以录制夹具验证输入→canonical 输出 |
| 夹具（fixture） | 提前录好或构造好的"假但真"的样本，让测试不依赖真机、网络和外部系统 | `tests/fixtures/`、`store/offline-demo/`；离线 profile 页面标注"证据来自录制夹具" |
| 合成夹具 | 不是录来的、是人工按规则构造的测试数据，配套密封环境使用 | S2 门禁的 hermetic 合成用例库 |
| 死信（dead letter） | 处理失败的条目不丢也不卡死全流程，单独关进"问题箱"待返工，且 UI 可查 | `dead_letters` 表（core/requirement.py、testcase.py 的 ParseError 载荷）；解析失败/嵌入补偿失败都进死信 |
| 投影（projection） | 从一个或多个数据源各取字段，派生一份只读视图/快照，不动源数据 | 三处：用例关系的四源投影（relation_building `_gather_inputs`）、提示词投影快照（非置顶上下文字节级锁死）、负反馈投影（反馈派生 bad case） |
| oracle | 判断测试输出对不对的参照标准，说白了就是"预期结果"的学名 | 结构化用例 `{前置,步骤[],oracle[]}`，分 UI/日志/状态/人工四类；"oracle problem"= 用例只有步骤没有预期 |
| 门禁（gate） | 切片收尾必须达标的机器校验线，指标不过不许进下一片 | 指标门禁（[06](06-核心评测指标体系.md)）+ 探针脚本 A1–A21 |
| 红证 / 红→绿对照 | 故意把代码改坏，证明测试真的变红；再还原变绿——以此证明测试抓得住 bug，不是"假全绿" | S1.6 tree-sitter 红→绿、S2.6d 改坏专家关键词 exit 1 后还原；FR-EX-007 AC3 强制要求 |
| 盲标 | 专家先独立列清单封存，再揭示 AI 的答案对比，防止看着 AI 答案事后凑意见 | 测试点专家盲标（FR-TD-002）、oracle 专家盲评；POC 期自己分饰但流程保留 |
| 写根 | 回写文件落地的根目录，配置化；语料仓是只读红线，一个字都不许写进去 | 默认 `data_dir/case-writeback`，MarkdownCaseRepository 策略守卫 |
| 留痕 | 每做一步都落一条记录，事后能还原"谁、何时、基于什么做了什么" | ETL 每步状态、intent_source 三源留痕、审批四要素 |
| 证据账本 | 每次工具调用和每条结论都记账，能从最终输出反查到全部来源 | Evidence/EvidenceRef 模型，traceId 与 Langfuse、TestRun 贯通 |
| 对账 | 拿本地账本和外部系统的真实状态逐条比对，修掉两边不一致 | FR-WR-002：定时对账修复幻影记录，缺失补建、残留回收 |
| 幻影记录 | 本地账本有、外部系统实际没有的中途态记录（通常是发出去那一刻进程被杀） | outbox pending 记录的对账修复对象 |
| outbox（发件箱） | 要对外部系统做的写操作，先在本地账本持久化再派发，中途被杀也能幂等续上 | OutboxRecord 状态 pending/sent/confirmed/failed |
| 幂等（idempotent） | 同一个操作重复做 N 次，效果和做一次完全一样 | 幂等键 + 内容寻址 ID；杀进程重启不重复建工单/评论 |
| 内容寻址 | 用内容本身的哈希值当 ID，内容相同 ID 就相同，天然去重幂等 | 用例关系 URN 用 sha1[:12]、回写 Markdown 同名同内容不重复落盘 |
| 回放/重放（replay） | 拿录制好的事件/响应重新驱动一遍流程，常用于验证幂等和离线演示 | CI 事件 JSON 可 replay、模型录制响应、checkpointer 快照重放 |
| 降级 | 某个依赖挂了或不可信时，走简化路径继续服务，并显式挂出"降级"标记，绝不静默假装正常 | 向量库故障→FTS-only；引用校验失败→输出"未知"；模型超时→结构化重试上限后降级 |
| canonical（规范化） | 不管外部系统数据长什么样，进系统都归一成同一种标准表示 | canonical Issue/TestCase 模型；契约测试断言 canonical 输出 |
| hermetic（密封） | 测试自带全部依赖、零外部网络零外部服务，用临时库合成数据，跑完即弃 | eval hermetic 副本、各 probe 的 tmp_path 装配 |
| hostless（无宿主） | iOS 语境：不起模拟器、不装 App 就能跑的纯逻辑测试，秒级 | AlarmKitSpikeTests hostless 套件先于 XCUITest 打通；core 纯函数测试也自称 hostless |
| fail-closed（失败即拒） | 校验不通过时默认拒绝/报错，而不是放行——宁可不可用不可错 | 引用未命中不渲染、证据 dossier 缺证据直接失败、白名单外工具调用=0 |
| dry-run（空转） | 只在本地记账本，不真的调用外部写接口 | FR-WR-003 默认开启，审批后才真正派发 |
| 防腐（层/门禁） | 核心代码不许认识任何外部 SDK 和具体技术，靠 import 检查强制隔离 | `scripts/import_lint.py`：core 零三方零 IO，grep 不到 xcodebuild 等 |
| 探针（probe） | 独立可跑的验收脚本，一条命令出一份 JSON/MD 报告，不起服务不占端口 | `scripts/*_probe.py`，对应 A7–A21 门禁 |
| 确定性脊柱 | 不经过模型、按固定规则必然产出的基础结果，保证"最差也有一份零编造的兜底" | testpoint.py：每活跃 FR 一条功能点、每 NFR 一条规则点；模型只许在白名单内补点 |
| 骨架 | 自由文档抽成的固定四段结构 | 需求骨架 = {功能点, 规则, 验收标准, 涉及模块}，缺 AC 显式标缺不编造 |
| 白名单 | 明确允许的清单，清单外一律拒绝 | 工具白名单、模型补点来源白名单（确定性三源之外才许模型补） |
| 四元组 | 每份评测报告必须标注的四个版本号，换了任何一个结果都不可直接对比 | 数据版本 / 模型版本 / prompt 版本 / 参数版本 |
| golden set（金标题集） | 冻结的一套标准考试题，系统改前后跑同一套，分数升降才可信 | 30 题 golden v1（S1）→ ~100 题（S5），与入库语料严格隔离防泄题 |
| few-shot（少示例） | 提示词里附几个输入输出范例，教模型照格式做 | L3 规则资产；人工审批 diff 回流成 few_shot 示例 |
| 幻觉（hallucination） | 模型编造证据里根本不存在的内容 | 幻觉点率门禁 ≤0.05；幻觉死信单独记录 |
| bad case（坏例台账） | 用户点踩或评测暴露的失败案例，统一进台账做分诊、补考题、回归验证 | FR-EV-005；badcase 状态机 + 六端点（A17），负反馈投影幂等落账 |
| 漏点 | 专家清单里有、AI 清单里没有的测试点 | P0/P1 漏点门禁 = 0 |
| 忠实度（faithfulness） | 答案的每条陈述是否都能被检索证据支撑，不夹带私货 | RAGAS 语义裁判指标，S1 门禁 ≥0.9 |
| live-verify（现场核验） | 代码类问题回答前，实时读 HEAD 代码复核符号还在不在、函数体有没有变 | FR-QA-002；索引滞后于 HEAD 时以 HEAD 为准 |
| stale（过期标记） | 代码重构后，旧索引条目与当前代码对不上了，挂过期标记等待重建 | FR-FRS-002：高价值立即 reindex，低价值懒重建 |
| reindex（重建索引） | 把变更后的代码/文档重新切块嵌入、替换旧索引 | 同上；符号锚定稳定 SymbolId 不绑行号 |
| flaky（不稳定用例） | 同一份代码时过时不过的用例，通常是时序/环境污染问题 | S3.4 钉版：**同一 commit** 重跑（≥2 次观察）同时出现 passed 与 failed/error 才判 flaky；全失败不是 flaky（那是复现缺陷证据），误判会让真缺陷逃逸 |
| 浅校验 | 对零引用草稿只做轻量结构校验就触发重试，不浪费完整生成 | 引用治理 P1：零引用草稿浅校验重试一次 |
| rerank（重排序） | 多路召回合并后再用更贵的模型/规则精排一遍 | 混合检索 FTS5+Chroma 融合后的排序环节 |
| embedding（嵌入） | 把文本变成一串向量数字，语义相近的文本向量距离近 | Ollama dmeta 嵌入，存 Chroma；故障有嵌入补偿/死信 |
| 联邦（federation） | 不缓存结论，用到时实时去源系统取 | L0 实时联邦层：代码/CI/工单状态不落地结论 |
| 租约（lease） |  worker 认领任务时拿到的"限时使用权"，到期没干完就视为进程已死，任务可被别人重领 | SqliteQueue 认领即写 `lease_expires_at`（默认 300s）；未过期绝不抢，防同一任务两个 worker 双跑 |
| 重领 / 死信（requeue / dead letter） | 租约过期后的两种归宿：还没重试到上限就重新排队，到上限就判失败关进问题箱，防毒消息无限循环 | `decide_reclaim` 纯判定（lease_expired / max_attempts_exceeded），worker 启动先回收再干活 |
| 重跑配额（rerun quota） | 每个预算键每天最多重跑几次，超了直接拒绝，防止坏用例把机器资源吃光 | `rerun_budget` 表 + request_id 唯一约束；崩溃重放不双扣，拒入不留幻影记录 |
| 执行账本（test_runs） | 每次测试执行的权威台账：排队就先落账，跑完把完整结果（raw_json）存进去 | run_id 由幂等键内容寻址；队列 job 是派发件、账本才是事实源 |
| Surefire / JUnit XML | Java 生态事实标准的测试报告格式（Maven Surefire 插件产出），XML 描述套件/用例/失败堆栈 | `junit_report.py` 仅用 stdlib 解析成语言中立 TestRun，与 xcresult 走同一模型（FR-EX-001） |
| 协作式取消 | 不强制杀进程，只打一个"请停下"的标记，worker 在检查点自己读到后体面收尾 | jobs.cancel_requested；认领瞬间与队列双读防竞态，强杀留给超时逻辑 |
| 环境租约（env lease） | 跟"任务租约"不是一回事：任务租约借的是队列里的 job，环境租约借的是一台具体模拟器（udid），限时 300s，到期可被回收再分配 | `SimctlEnvironment` 内存登记（POC 单 worker），租约 ID 内容寻址；回收时尽力 `simctl shutdown`（幂等），多进程设备云是 P2 |
| 先租后跑 | worker 必须先从 EnvironmentPort 拿到环境租约、把 udid 透传进请求 labels，runner 才允许起 xcodebuild；labels 里没 udid 直接拒跑 | 防"无设备身份裸跑"；成功/超时/异常三个出口都必须释放租约，设备不泄漏 |
| 能力标签 / 未覆盖层 | 能力标签是环境与请求各自贴的能力清单（如 `ios.simulator`、`ui.automation`）；模拟器物理上给不出的真机能力（后台音频/推送/签名）叫"未覆盖层"，必须显式拒绝并说明，不许冒充已验 | `evaluate_capabilities` 纯判定；真机独占能力拒在 acquire 阶段，runner 零调用（不硬跑） |
| resultBundlePath | xcodebuild 结果包（xcresult）的产出目录参数；该目录已存在时 xcodebuild 拒绝覆盖 | `XcodeTestRunner` 起进程前先删旧包（FR-EX-002 AC3），路径按 run_id 内容寻址命名 |
| xcresult / xcresulttool | xcresult 是 xcodebuild 跑完留下的结果包（用例树+失败信息+截图录屏附件）；xcresulttool 是苹果自带的读取/导出命令行 | S3.3 `XcresultToolResultParser` 三命令：get tests 展平用例、get attachments 清单、export 导字节；未知形态 fail-closed |
| os_log | 苹果统一日志系统（App 与系统进程同一套），`simctl spawn <udid> log show` 可按谓词+时间窗导出 | `OsLogQueryAdapter` 实现 LogQueryPort；谓词与时间窗原样回显，是可复现证据的一部分（FR-EX-006 AC1） |
| NDJSON | 一行一个 JSON 对象的文本格式（Newline-Delimited JSON），`log show --style json` 的输出形态 | 适配器逐行解析：坏行计数留痕不中断整窗，样片封顶 3 条防撑爆响应 |
| 时间窗查询 | 只取 `[start, end]` 闭区间内的日志，不用 `--last 20m` 这类相对时间（事后无法复现） | core 纯函数过滤一道 + 服务端 `--start/--end` 一道（纵深防御），窗外条目不灌入知识库（AC2） |
| ffmpeg 抽帧 | 把失败录屏 .mp4 按固定帧率抽成 PNG 序列做人肉/视觉取证 | `ffmpeg_commands.py` 纯拼 argv，fps 白名单 1..30 整数，真实 ffmpeg 仅手动探针不进门禁 |
| 失败归因（五候选） | 测试失败后回答"为什么红"：真缺陷 / 用例过期 / flaky / 环境失败 / 产品改动五个候选，先列多候选再用决定性证据区分 | S3.4 `attribution.py` 四条确定性规则（FR-EX-007）；每条规则只在有正向证据时开火，规则版本戳 `attribution-rules-1` 进每个 verdict |
| needs_human（交人审） | 第六类裁决：证据不足或候选置信拉不开差距时，不硬猜，升级给人 | 置信地板 0.6 以下无候选、前两名差 ≤0.1 并列、不对称护栏拦截都回 needs_human，并保留冲突候选给人审复核（AC4） |
| 不对称护栏 | 规则向"别冤枉/别放过真缺陷"倾斜的保护：真缺陷候选 ≥0.7 在场时，非缺陷类必须凭明显更高置信（差 >0.1）才能赢，否则交人审 | 把真缺陷收口成 flaky/过期是代价最高的错误；红证：拆护栏后误误导率冲到 0.4，门禁立刻红 |
| 证据账本（evidence ledger） | 每次归因携带的证据清单，verdict 引用的每个 ref 都必须能在账本里回溯到来源（重跑记录/断言对照/日志/diff/环境信号/变更单） | 结构化信号缺同源账本条目整包 fail-closed；workers 组包、core 只判定，零 IO |
| 混淆矩阵 | 行是人工真值（ground truth）、列是机器判定的 6×6 对照表，每个格子记"真值 A 被判成 B"的例数 | `attribution_eval.py` 36 格预建，从矩阵算每类精确率/召回率；缺席类别零除返 None，不伪造 0 |
| 误误导率 | 真值是真缺陷、却被机器收口进四个非缺陷类别（过期/flaky/环境/产品改动）的比例；判 needs_human 不算误导（弃权不背锅，因为人审还能兜住） | 门禁 ≤0.02（FR-EX-007 AC2）；与真缺陷召回 ≥0.95 配对，一个防漏抓一个防错放 |
| 证据充分率 | 机器敢下结论的比例 = 1 − 弃权率（弃权 = 判 needs_human）；衡量"多少 case 不需要人接手" | 门禁 ≥0.9；40 例合成盲标实测 0.925（3 例弃权），充分率与准确率分开看，敢判不代表判得对 |
