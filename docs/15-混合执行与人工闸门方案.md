## 1. 要解决的问题

S3 打通的 xcodebuild 闭环只覆盖「单进程内 UI 操作 + UI/日志断言」。真实 P0 用例存在两类系统判不了的环节：

1. **圈外刺激**：锁屏、按物理侧边键、`sudo log collect` 等动作不在自动化能力圈内（[14](14-真机刺激动作方案对比（锁屏-解锁-侧边键）.md) 已证 HID/CGEvent 合成输入在模拟器与真机均惰性；真机 DH AX 仅 Home/Rotate/Screenshot 三动词可达，Lock/Siri 等菜单灰显）；
2. **感官裁决**：铃声是否响起、震动是否发生，系统侧只有间接证据（os_log 事件链、录屏抽帧），最终体感必须由人确认。

朴素做法会把一条用例割成「自动段 A → 人工段 → 自动段 B」三段互不相干的执行记录，丢掉用例完整性与因果链。本方案的目标：**一条 TestCase 不拆分，派生出一份可恢复、可审计、人机共编的混合执行计划，全程 runId/会话 id 贯通，人工环节有弹窗、有超时、有结构化裁决单，且人工裁决必须绑定系统侧客观证据。**

## 2. 三层模型与零 DDL 约束

```
TestCase（既有，不拆、不改）
   │  人读规格：steps/oracles/preconditions 原文，lifecycle=active 才可派生
   ▼ 派生（纯函数，内容寻址）
hybrid-plan-v1（JSON 制品，落 store，不建表）
   │  有序步骤 + 结构化前置 + 裁决单规格 + 幂等键 + content_hash
   ▼ 运行时
hybrid session（会话游标/账本，raw_json 制品，不建表）
   ├─ 子 run：auto:xcodebuild 步骤仍走既有 RunStatus 五态状态机与租约回收
   └─ 会话层：SessionStatus 另立，只描述游标，不进数据库
```

纪律：

- **schema 保持 v15 零 DDL**。计划、会话检查点、闸门全部是 ArtifactStore 内内容寻址/文件态 JSON；现有 run 表、状态机、迁移闭集一行不动；
- 子 run 的失败语义不变（产品缺陷 → failed）；会话层新增的 `blocked` 只表达「基础设施/人工未就位」，与产品失败严格区分，不污染失败归因五候选；
- 计划是 TestCase 的**派生制品**：TestCase 修订后 hash 变化即新计划，旧计划与旧会话保留不删（历史证据不篡改）。

## 3. 五类执行方（actor 闭集）

| actor             | 能力圈                                                                   | 动作闭集（v1）                                                       | 失败姿态                      |
| ----------------- | --------------------------------------------------------------------- | -------------------------------------------------------------- | ------------------------- |
| `auto:xcodebuild` | 既有 XcodeTestRunner，一段 Swift 测试 = 一个子 run                              | `run_selector`（params.only_testing 非空）                         | 子 run 状态机裁决               |
| `auto:dh-ax`      | Device Hub AX 语义通道（真机已验三动词，[14](14-真机刺激动作方案对比（锁屏-解锁-侧边键）.md) E25–E27） | `home` / `rotate_left` / `readiness` / `state`                 | 元素缺失/窗口零尺寸 fail-loud      |

| `human:verdict`   | 人的感官/主观裁决                                                             | `sensory_check` / `other`（带裁决单）                                | 超时 → blocked；与日志冲突 → 人工复核 |

> H3 落地注记（2026-11-14）：`auto:dh-ax` 已接线 `home/rotate_left/readiness`，`state` 与 `auto:devicectl` 的 `list_devices` 在运行期分派器里显式拒绝（"尚未接线，拒绝静默跳过"）；`terminate_app` 按 **PID** 终止（devicectl 无 bundle 终止动词，PID 必须在 `params.pid` 显式声明，缺失即 fail-loud）。DH AX 生产 CLI 已入 `subsystems/scripts/device_hub_ax_cli.swift`，退出码契约：0 成功 / 2 进程缺失 / 3 参数非法 / 4 元素缺失或零尺寸窗口 / 5 AXPress 失败 / 6 AX 未授权或 Mac 锁屏。

## 4. 结构化前置条件

每个步骤声明零到多个前置条件，每条是 `kind + on_failure + repair?` 三元组。v1 支持六种 kind。探针只回答三态——`satisfied` / `unsatisfied` / `unknown`，**unknown 是诚实的能力圈边界不是失败**，按计划姿态收口：

| kind | H3 实际探针 | 三态语义 | 典型 repair |
| --- | --- | --- | --- |
| `device_unlocked` | `DhAxAdapter.readiness()` 的 `screen_locked` 字段 | false→satisfied；true→unsatisfied；Mac 锁屏（exit 6）/AX 树脱物化（exit 4，E31）取不到结论→unknown | `human_gate`（解锁归人） |
| `session_window_materialized` | readiness 的 `ok` + home/screenshot/rotate_left 三按钮可达性 | 全可达→satisfied；exit 4→unsatisfied；环境不可用→unknown | `dh_home` / `human_gate` |
| `portrait_orientation` | devicectl 截图落盘后 `png_probe` 读 IHDR 像素宽高（高>宽） | 竖屏→satisfied；横屏→unsatisfied；截图通道失败/PNG 非法→unknown | `dh_rotate_left`（转一步截一张，竖屏即停，上限 4 次；E27：按截图判不按次数） |
| `app_not_running` | **恒 unknown**：devicectl 词汇表无进程清单动词，主机侧无法枚举存活 App 进程 | 仅支持按显式 PID 终止，禁止假装 satisfied | `devicectl_terminate`（须带 `params.pid`） |
| `no_active_alarms` | **恒 unknown**：App 内闹钟库对主机侧不可见 | 清场效果归该段 xcodebuild 结果兜底验证 | `app_launch_purge_args`（`--ak-purge-dates` 等启动参数，无 IO，并入子 run 载荷） |
| `notification_permission` | **恒 unknown**：授权归属可能不在本进程，重置命令未必有效 | 只能人工现场确认 | 仅 `human_gate` + blocked |

修复动词闭集：`dh_home` / `dh_rotate_left` / `devicectl_terminate` / `app_launch_purge_args` / `human_gate`。其中 `human_gate` 只能配 `blocked` 姿态——能力圈外的事不能判产品失败。

**三级清理优先级**：① App 测试钩子（启动参数/测试菜单）> ② 宿主侧 DH AX / devicectl > ③ 人工闸门。前置建不起来时只有两种姿态：`blocked`（等人/等环境，可恢复续跑）或 `fail_loud`（直接失败），禁止带假设状态开跑。用例可重入性由此保证：串行执行的每条用例把前置显式写进计划，而不是依赖上一条用例「恰好」留了干净现场。

## 5. 计划契约（hybrid-plan-v1）

### 5.1 载荷结构

```json
{
  "plan_schema_version": "hybrid-plan-v1",
  "case_urn": "urn:testpilot:fs-cases:test_case:cases.md#TC-LOCK-01",
  "case_external_id": "TC-LOCK-01",
  "profile": "ios-local-poc",
  "project": "AlarmKitSpike",
  "steps": [
    {
      "step_id": "s1-purge-and-schedule",
      "actor": "auto:xcodebuild",
      "action": "run_selector",
      "params": {"only_testing": ["AlarmKitSpikeUITests/testLockRelay_schedule"]},
      "preconditions": [
        {"kind": "portrait_orientation", "on_failure": "blocked",
         "repair": {"verb": "dh_rotate_left", "params": {}}, "note": ""},
        {"kind": "no_active_alarms", "on_failure": "blocked",
         "repair": {"verb": "app_launch_purge_args", "params": {}}, "note": ""}
      ],
      "prompt": "",
      "verdict_form": null,
      "evidence_bindings": ["urn:testpilot:store:artifact:segA-xcresult"],
      "timeout_seconds": 300,
      "idempotency_key": "s1|TC-LOCK-01|schedule",
      "failure_policy": "abort_session"
    }
  ],
  "created_at": "2026-11-14T08:00:00Z",
  "content_hash": "<sha256，canonical JSON，剔除 created_at/content_hash>"
}
```

### 5.2 校验规则（计划期 fail-loud，`HybridPlanError`）

1. 至少一个步骤；`step_id` 全计划唯一；
2. actor/action 必须在 §3 闭集；xcodebuild 段必须声明非空 `params.only_testing`；devicectl launch/terminate 必须声明 `bundle_id`；
3. 人工步必须有非空 `prompt`（弹窗文案）；`human:verdict` 必须携带非空 `verdict_form`；自动步携带表单 = 非法；
4. 前置 kind、修复 verb 各走闭集；`human_gate` 修复只配 `blocked`；
5. 裁决表单字段 key 唯一；`choice` 字段必须给 `options`；
6. `require_evidence=true`（默认）的裁决步必须在 `evidence_bindings` 声明系统侧证据来源——**空口打勾在计划期就被拒**；
7. 仅 `lifecycle=active` 且非 `exploratory` 的 TestCase 可建计划；
8. 时间戳必须带时区；naive datetime 拒绝。

内容寻址与 `case-export-v1` 同纪律：canonical JSON（`sort_keys`、紧凑分隔、`ensure_ascii=False`）sha256，剔除 `created_at`/`content_hash`，跨时间戳稳定、随内容变。文件名 `hybrid-plan-<UTC时间戳>-<hash前8位>.json`。

## 6. 会话状态机与崩溃恢复

### 6.1 迁移闭集

```
pending ──▶ running ──▶ passed / failed / error（终态，不可变）
              │  ├─▶ awaiting_human ──▶ running（闸门响应）
              │  ├─▶ blocked ──▶ running（环境恢复，当前步重回 running）
              └──▶ canceled（终态）
```

- `awaiting_human`：闸门已挂出，等人工响应；`blocked`：基础设施态不满足（DH 窗口消失、设备掉线、闸门超时）。两者都是**挂起态不是失败**；
- 终态（passed/failed/error/canceled）任何迁出都是非法迁移，纯函数直接抛错；
- 单步状态：pending → running → completed/failed/blocked/skipped；只有 running 步可推进，对已处置步骤的重入显式拒绝。

### 6.2 检查点与幂等

- 每推进一个步骤，`SessionCheckpoint`（会话 id、plan_hash、会话状态、每步状态表、completed 列表、current_step_id、gate_ids、updated_at）整体重写落盘；进程被杀后凭最后检查点续跑，不依赖任何内存态；
- 每个步骤带 `idempotency_key`：重试时适配器凭键去重（xcodebuild 子 run 复用既有 run 幂等/租约机制；DH/devicectl 动作先 probe 后动作，天然可重放）；
- 检查点推进是**纯函数**（`advance_checkpoint` 不就地改入参，返回新对象），全部迁移规则有 hostless 红证测试钉死。

H3 落地形态（2026-11-14）：

- 持久化信封 `HybridSessionRecord = session_id + plan 载荷 + checkpoint + ledger`，单文件 `store/hybrid-sessions/hsess-<12hex>.json`，tmp+`os.replace` 原子写，session_id 由 `case_external_id|content_hash` 确定性派生（同用例同计划版本重放同 id，重建幂等）；
- `ledger` 追加记录每一步的探针审计、repair 痕迹、子 run 引用（run_ref）、闸门 id 与适配器返回摘要；前置人工闸门响应后重入同一 running 步骤时，凭 ledger 的 `precondition_gate/responded` 条目跳过对应前置，**不重复弹卡**；同一闸门重复 `resume_after_gate` 显式拒绝（防人工步双推进）；
- 编排器 `hybrid_runner.py` 提供 `start_session / drive_until_wait / resume_after_gate / unblock / get_session`：自动步连环推进到 awaiting_human/blocked/终态（迭代上限 100 防失控）；基础设施不可用（`AdapterUnavailableError`）→ blocked，动作失败按步骤 `failure_policy` 收口 failed/blocked，两类语义严格区分；
- xcodebuild 段经 `ChildRunPort` 协议派发（`ChildRunRequest{only_testing, launch_arguments, idempotency_key}` → run_ref）。H3 测试用假件；**H4.1 已落真实实现** `workers/hybrid_child_run.py::ExecutionServiceChildRun`：经既有 execution_service `submit_execution` 入队（幂等键 `hybrid:<step key>` 命名空间，与 `impact:` 重跑源防撞、`daily_budget_key=None` 不占重跑配额），再轮询 run 账本到五态终态才交还 run_ref——s1 子 run 未结束不返回，os_log 采集时序与本文 §8 约定一致；崩溃续跑重放返回同一 run_id，等待循环自然接住。失败严格分型：产品失败（FAILED）抛 `ChildRunFailedError` 走步骤 `failure_policy`；ERROR/TIMEOUT/CANCELED/等待超时/基础设施未就位抛 `ChildRunUnavailableError`（`AdapterUnavailableError` 子类，带 runner worker 未排空 runbook 提示）→ 会话 blocked，不污染产品失败归因。scm 缺失等装配问题 fail-loud。
- **`launch_arguments` 是账本追溯字段，不穿越 xcode argv**：`xcodebuild -help` 无 `-launchArguments` 旗标，探针解析出的 `--ak-purge-dates` 等清场参数无法从主机 CLI 注入；真实生效路径是 Swift 侧 `XCUIApplication.launchArguments`（[12](12-用例导出与Xcode执行闭环方案.md) §3.2 生成契约，外部 Agent 按 prompt 包写进段 A 方法）。该字段经 `TestExecutionRequest.launch_arguments`（默认空 list）随 request_json 零 DDL 持久化，仅用于账本审计「本步打算清哪些场」，xcode argv 不消费它。

## 7. 人工闸门与结构化裁决

### 7.1 闸门生命周期（H2 已落地，文件态零 DDL）

实现：`adapters/gate_store.py`（`FileGateStore`，落 profile 写根 `data_dir/gates/<gate_id>.json`，tmp+os.replace 原子写，gate_id 闭集正则防路径穿越）+ `workers/gate_service.py` + `orchestrator/gate_api/` + Web `app/gates/`。

1. 会话游标走到人工步 → `build_gate_request` 生成闸门载荷（gate_id 由 `session_id|step_id` 哈希确定，**崩溃重建同 id，天然幂等**：重复 POST 挂单返回既有记录），状态 `pending`，带绝对 UTC deadline；
2. Web `/gates` 页 5s 轮询拉取全量闸门并按待处理/已闭环分组，pending 卡片展示倒计时与裁决表单（不做 osascript/系统通知，headless 友好；不做 SSE）；
3. **过期是读时现算而非定时任务**：任何 GET 到达时 service 用注入时钟对 pending 单比对 deadline，过期即持久化 `expired`（测试可注入未来时间，零 sleep）；
4. 人在 deadline 前响应 → `responded`，裁决挂在同一 JSON 的 `response` 字段；过期单响应被 core 拒绝（422「请先续期」），`renew` 把 expired 重开回 pending（会话 blocked 解除），`abandon` 走 canceled；已响应闸门不可取消（裁决留痕不可抹）；
5. HTTP 端点：`POST /api/gates`（挂单）、`GET /api/gates?status=`（队列）、`GET /api/gates/{id}`、`POST /api/gates/{id}/respond|renew|abandon`；`HybridPlanError` 统一映射 422，未知/非法 gate_id 映射 404；
6. 闸门状态闭集：pending / responded / expired / canceled。

### 7.2 裁决单规则

`verdict_form` 声明字段（boolean / choice / text，required 可控），响应 `HumanVerdict` 校验：

- 必填字段齐；boolean 必须是真布尔；choice 值必须在 options 内；text 非空；表单外字段拒绝；
- **证据强制**：`require_evidence=true` 时响应必须带至少一个系统侧证据 URN（os_log 事件链制品、录屏抽帧、devicectl 截图），并记录 `decided_by` 见证人与 `decided_at`；
- 人工结论与客观证据冲突时（例：人判「未响铃」但 os_log 存在完整响铃事件链）：**不静默覆盖任何一方**，会话转人工复核队列，两份结论并排留痕，复核决定计入归因。

### 7.3 典型裁决单（锁屏响铃场景）

| 字段 key | 类型 | 选项/说明 |
| --- | --- | --- |
| `ringtone_heard` | boolean | 是否听到铃声 |
| `vibration_felt` | boolean | 是否感到震动 |
| `confidence` | choice | high / medium / low |
| `note` | text，可选 | 环境噪声等备注 |
| 证据 URN | 强制 | os_log 响铃事件链 + 接力页录屏 |

### 8.2 `testpilot-hybrid` 驱动 CLI（H4.2 已落地）

入口脚本 `testpilot-hybrid`（workers 包第 18 个 console script），把编排器函数面收敛为五个子命令，供独立进程/人工 runbook 驱动：

| 子命令 | 作用 | 关键参数 |
| --- | --- | --- |
| `start` | 载入计划 JSON 建/重建会话（幂等，同 hash 返回同 session） | `--plan <plan.json>` |
| `drive` | 自动步连环推进到下一个 awaiting_human/blocked/终态 | `--session hsess-xxx --udid <硬件UDID> --bundle-id <bundle>` |
| `resume` | 闸门已响应后续跑（前置/步骤闸门内部自动区分路由） | 同上 + `--gate gate-<12hex>` |
| `unblock` | 环境阻塞解除后续跑（当前步重回 running） | `--session --udid --bundle-id` |
| `get` | 只读打印会话快照（计划/检查点/账本单 JSON） | `--session` |

契约：stdout 始终是单个 JSON 快照（`model_dump(mode="json")`），stderr 只放装配日志；业务/装配硬错误统一 stderr `[hybrid-worker] 被拒: <Type>: <msg>` + **exit 2**，成功 exit 0；设备目标必须显式 `--udid`/`--bundle-id`（隐式 booted/默认 bundle 在真机会打错目标），缺参 exit 2。profile 由 `TESTPILOT_PROFILE` 环境变量选择，**值必须是 yaml 完整路径**（如 `config/profiles/ios-local-poc-device.yaml`，传裸 profile 名会报「profile 配置不存在」，见 [13](13-系统使用说明书（克隆到演示全流程）.md) §3）；真机走查三进程（hybrid CLI、`testpilot-runner worker`、uvicorn 闸门 API）必须同一 device profile，否则队列/闸门/会话落在不同 data_dir 互不可见。

**闸门响应不在本 CLI**：人在 Web `/gates` 页或 `POST /api/gates/{id}/respond` 提交裁决（expired 单先 `renew` 续期），闸门转 `responded` 后 `resume --gate ...` 才合法——对 pending/expired 闸门 resume 会被纯函数拒绝（防双推进）。

### 8.3 锁屏响铃 → 侧键 → 接力页 E2E 人工 runbook（H4.4，人工项）

本 runbook 是**人工执行项**：自动化只负责自动段与闸门挂单，锁屏/侧边键/感官裁决永远归人。可执行探针骨架与带本机参数的副本在 gitignored 目录 `subsystems/out/hybrid-tca1/runbook/`（**永不进 verify_s0、永不入库**）；下列命令均为通用形式，设备参数以环境变量传入，不含机器绝对路径。

前置条件：① 语料仓演示分支已携入外部 Agent 生成的两个方法并通过模拟器 `build-for-testing` 构建门禁与 `testpilot-scan-generated-swift`（exit 0）；② 真机已连接、被测 App 已安装；③ TestPilot 侧长循环 `testpilot-runner worker` 可排空 execution_service 队列（否则 s1 子 run 等待超时 → blocked，按提示 runbook 处理）。与 [13](13-系统使用说明书（克隆到演示全流程）.md) §5 场景 A 的边界：**§5.6 automation-map 与 §5.7 手工 submit/run-once 不适用本流程**——混合子 run 直接以计划 `only_testing` 构造 `CaseSelector` 入队（不查 map），入队动作由 `drive` 内部完成，人工只起 worker 长循环。

```bash
# 0) 环境变量（具体值见 gitignored 探针骨架，不写入入库文档；profile 必须是完整 yaml 路径）
export TESTPILOT_PROFILE=config/profiles/ios-local-poc-device.yaml
export TCA1_UDID=<硬件UDID>
export TCA1_BUNDLE=<被测 bundle id>
PLAN=subsystems/out/hybrid-tca1/TC-A1.hybrid-plan.json

# 1) 建会话（幂等；记下 stdout 的 session_id，预期 hsess-44466b93d696）
testpilot-hybrid start --plan "$PLAN"

# 2) 推进：s1 段 A 子 run（execution_service 真实队列，轮询到终态）
#    → s2 devicectl 基线截图 → s3 人工锁屏闸门挂出，会话 awaiting_human
testpilot-hybrid drive --session "$SID" --udid "$TCA1_UDID" --bundle-id "$TCA1_BUNDLE"

# 3) 人在 /gates 页响应 s3 前置/动作闸门（现场确认通知权限并锁屏），然后续跑
testpilot-hybrid resume --session "$SID" --gate <gate-id> \
  --udid "$TCA1_UDID" --bundle-id "$TCA1_BUNDLE"

# 4) s4 到点响铃 → 人按一次物理侧边键并解锁 → 响应闸门 → resume
# 5) s5 感官裁决单：ringtone_heard/vibration_felt/confidence/note +
#    强制证据 URN（os_log 响铃事件链 + 录屏/截图），在 /gates 提交后 resume
# 6) s6 段 B 子 run（app.activate() 接力页断言）；drive 收口到 passed/failed
testpilot-hybrid drive --session "$SID" --udid "$TCA1_UDID" --bundle-id "$TCA1_BUNDLE"

# 任意时点只读查看；blocked（设备掉线/DH 窗口消失等）恢复后用 unblock 续跑
testpilot-hybrid get --session "$SID"
testpilot-hybrid unblock --session "$SID" --udid "$TCA1_UDID" --bundle-id "$TCA1_BUNDLE"
```

验收口径：终态 `passed` 且账本六步证据齐备（两段 xcresult run_ref、基线截图、三个闸门 responded 记录、os_log 事件链 URN）；任何 blocked/error 如实保留会话 JSON，不许改账本造绿。模拟器永远只过构建门禁——TC-A1 的侧边键/全屏闹钟/铃声震动是 📱 真机-only，本地环境暴露不了（工程纪律：哪层已验、哪层只能真机验，须在执行记录里写清）。

> s5 证据生产的诚实边界（2026-11-16）：混合编排器当前不自动调 os_log 适配器，上文「s1 结束即启动 os_log 采集」是目标形态；真机 `collect_mode=manual`，os_log 响铃链由人工按 [03 语料工程与实测环境](03-语料工程与实测环境（AlarmKitSpike）.md) §3.7 两步法采集（本机实测 `log collect` 需提权 rc=77，sudo 纯人工），录屏走 QuickTime 选真机（devicectl 无录屏动词），具体命令与归档位置在 gitignored 探针骨架 `out/hybrid-tca1/runbook/tca1_e2e_runbook.md` §6。core 对裁决单只校验证据 URN 列表非空、不校验制品存在，证据真实性靠人工纪律与 note 路径回溯。

### 8.4 DH AX 四动词真机复跑人工指引（H4.4，人工项）

生产 CLI `subsystems/scripts/device_hub_ax_cli.swift`，四动词 `readiness` / `home` / `rotate-left [--times N]` / `screenshot`，`xcrun swift device_hub_ax_cli.swift <verb>` 调用。复跑前**三个硬前置**缺一不可：

1. **Mac 上 Device Hub 窗口保持打开**（AX 元素由该窗口物化；窗口消失/零尺寸 → exit 4，探针只拿到 unknown/unsatisfied）；
2. **Mac 已解锁**（`CGSSessionScreenIsLocked=1` 时 readiness 直接 exit 6，非设备问题）；
3. **辅助功能（AX）授权已授予**运行终端/进程（未授权 → exit 6；授权归属 macOS 隐私设置，重置命令未必有效，须人工现场确认）。

复跑顺序：先 `readiness` 看 `ok` 与三按钮可达性 → `screenshot` 验证截图通道（PNG 经 `png_probe` 验 IHDR）→ 需要竖屏修复时 `rotate-left --times N`（按截图判不按次数，上限 4 次）→ `home` 回桌面。退出码闭集：0 成功 / 2 Device Hub 进程缺失 / 3 参数非法 / 4 元素缺失或零尺寸窗口 / 5 AXPress 失败 / 6 AX 未授权或 Mac 锁屏——**非零一律 fail-loud，没有静默成功**；混合会话里对应步骤收口为 blocked（环境态）而非产品 failed。

## 9. 转场与生成纪律（H5 红线，已落地为静态门禁）

1. **轮询替死等**：生成的 Swift UI 测试一律 `waitForExistence(timeout:)` 轮询，禁止固定 `sleep(`/`usleep(`/`Thread.sleep`（**GS-001 已落地**：`generated_swift_lint` 注释/字符串遮罩后扫描，hostless 红证测试覆盖植入必红、回退转绿）；
2. **双超时断言**：除「新元素出现」外，同时断言「旧页面消失」，防同名节点假绿；
3. **接力段用 activate 不用 launch**：段 B 类附着场景 `app.activate()`，冷启动会销毁系统接力场景（**GS-002/GS-003 已落地**：同方法 activate+launch 并存、或两次以上 `.launch(` 均扫红；契约全文与六类前置承接模板见 [12](12-用例导出与Xcode执行闭环方案.md) UI 分支规则 5/6）；
4. **AX err=0 不作数**：DH AX 动作效果一律以 devicectl 截图前后对照判读（E24 教训），截图尺寸/页面不符即 fail-loud；
5. 每用例干净启动、互不污染（前置 probe/repair 保证，见 §4）。
