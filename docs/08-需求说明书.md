## 1. 总体性需求

### FR-CFG-001 项目与仓库配置（P0，S0）
系统支持以配置文件（`.testpilot/config.yaml` + 环境变量）注册一个项目：项目名、被测仓库根路径
（**禁止代码内写死绝对路径**）、默认分支、技术栈(iOS)、适配器选型、模型端点、数据目录。

- AC1：不修改代码，仅改配置即可把仓库路径/scheme/模拟器 udid 换到另一工程；
- AC2：启动时校验必填配置，缺失项给出明确错误；
- AC3：同一份镜像以不同 profile（人话：一套预设的装配方案，改配置就切换真实/离线适配器；ios-local-poc / offline-demo）启动装配不同适配器。

### FR-CFG-002 端口/适配器架构（P0，S0）
核心工作流只依赖 `testpilot-core` 中的端口接口与统一模型；所有外部系统（Git、文件、xcodebuild、
工单、CI、模型、向量库、日志、制品、环境）经适配器接入。

- AC1：`testpilot-core` 中 grep 不到 xcodebuild/simctl/gradle、任何 SDK、fixture 绝对路径（CI lint 强制）；
- AC2：每个端口至少有"真实适配器 + 离线录制适配器"两种实现可切换；
- AC3：适配器切换不引起 orchestrator/workflow 代码改动（依赖注入 + 配置装配）；
- AC4：每个适配器有契约测试（只验约定输入输出、不看内部实现；以录制夹具（提前录好的样本，离线替代真机/外部系统）验证输入→canonical（归一后的统一标准表示）输出）。

### FR-CFG-003 统一领域模型与 URN（P0，S0）
系统内所有外部资源以 URN（系统内统一资源名，外部系统自己的 ID 不当主键）
`urn:testpilot:<system>:<type>:<id>@<version>` 标识，外部 ID 不作为核心主键。

- AC1：同一工单在 JSON adapter 与（未来）Jira adapter 下核心模型字段一致；
- AC2：模型变更走版本化（schema 版本号 + 迁移脚本）。

### NFR-001 可移植性（P0）
所有机器相关路径、udid、scheme、端口经配置传入；生成物（store/、.venv、xcresult、模型缓存、
`__pycache__`、运行时工单库）全部位于数据目录且在 `.gitignore`。

### NFR-002 隐私与数据边界（P0）
默认本地模型；任何发往云端模型的请求必须有显式配置开关，且按文档密级可关闭；
日志与 trace 中不记录密钥；展示层不暴露无关用户数据。

## 2. 连接器域（CON）

### FR-CON-001 Git 代码连接器（P0，S1）
经 `CodeRepositoryPort` 提供：commit 列表、diff、文件内容、blame、符号在指定 commit 的快照；
**不依赖 commit message 质量**，变更以 diff + AST 符号集合表达。

- AC1：给定 base/head 返回 ChangeSet（变更文件、变更符号、增删改类型）；
- AC2：message 为空的 commit 也能产出符号变更集；
- AC3：读取指定 commit 的文件内容（live-verify 使用）；
- AC4：仓库不可达时返回可识别错误并降级（走简化路径并显式标注，不假装正常），不抛未处理异常。

### FR-CON-002 文件文档连接器（P0，S1）
经 `KnowledgeSourcePort` 只读扫描配置的文档目录（Markdown），记录 URI、hash、mtime、
权威等级（配置/可覆盖）、密级标签；支持增量（基于 checkpoint）。

- AC1：首次全量、再次扫描只返回变更/删除文件；
- AC2：删除/移动文件产生删除事件而非残留索引；
- AC3：语料盘点视图可导出（位置/更新时间/hash/权威等级），供知识开建 K1 使用。

### FR-CON-003 用例文档连接器（P0，S2）
解析结构化 Markdown 用例为 `{前置条件, 步骤[], oracle[]}`（oracle=判断输出对错的参照标准，
即"预期结果"的学名）；对"只有步骤无预期"用例打 `oracle_missing` 标记，不丢弃。

- AC1：V1测试用例文档全量解析成功，缺预期用例被正确标记；
- AC2：解析失败条目进死信表（人话：失败条目单独关进"问题箱"，不丢、不阻断整批、UI 可查可返工）并可在 UI 查看，不阻断整批。

### FR-CON-004 JSON 工单适配器（P0，S3）
经 `TicketPort` 以 JSON fixture 实现查询与（受控）写入：读 `fixtures/tickets/*.json`；
写操作落到运行时数据目录，具备与真实系统一致的搜索/建单/评论/状态流转接口语义。

- AC1：搜索返回 canonical Issue 模型；
- AC2：create/add_comment/transition 需要幂等键，重复键不产生重复记录；
- AC3：写操作未经审批直接调用被策略层拒绝。

### FR-CON-005 CI 事件适配器（P0，S3/S4）
消费 `PipelineFinished` 等事件（JSON 文件可 replay（拿录制事件重新驱动流程，验幂等），信封 schema 见 04 §8），
并从 xcresult（本地路径/制品 URI）解析流水线结果。

- AC1：给定事件文件可重放入口且幂等（同 event_id 二次投递不重复处理）；
- AC2：事件缺字段时进死信并报错，不静默忽略。

### FR-CON-006 模型网关适配器（P0，S1）
经 `ModelGatewayPort` 提供 chat/structured output/embedding；默认 Ollama，可切 OpenAI 兼容端点；
含超时、重试、显式降级标记与 token 计量。

- AC1：同一 workflow 切模型只改配置；
- AC2：structured output 解析失败有重试次数上限与降级路径；
- AC3：每次调用记录模型版本、token、延迟到 trace。

## 3. 知识加工与检索域（ING/KNO）

### FR-ING-001 加工管线（P0，S1/S4）
管线：解析归一化 → 质量评分 → 实体链接 → 切块嵌入 → 元数据登记；每步状态留痕（落记录、事后可追溯）可查可重跑。

- AC1：每个文档可查看其切块、质量分、实体关系、content_hash、来源版本；
- AC2：单文档失败不影响整批，失败可单条重试；
- AC3：重跑对同一输入幂等（不产生重复切块）。

### FR-ING-002 代码 AST 切块（P0，S1）
Swift 源码按 SwiftSyntax 以类/函数为单位切块，带符号 ID、文件、行范围（版本化）、签名。

- AC1：`MissionCoordinator.schedulePrimary` 等符号可被独立召回；
- AC2：同步产出最简调用/被调用关系（至少同文件内）；
- AC3：提供 AST 切块 vs 纯文本切块在同一题集上的命中率对比数据（06 §4）。

> **实现注记（2026-11-03 选型决策）**：S1.1 的 AST 角色由 core 内零依赖的
> Swift 词法扫描切块器承担（注释/字符串屏蔽 + 大括号配平 + 行首声明正则；
> 见 `subsystems/packages/core/.../chunking.py`），因为 SwiftSyntax 是 Swift 侧库、
> Python 入库管线无法直接调用。**S1.6 评测期按 AC3 做数据驱动的选型复核**：
> 在 adapters 层引入 tree-sitter（`tree-sitter-swift` 等 grammar 以 optional
> dependency group 安装，不破坏 core 零三方红线），与词法器对同一 30 题 golden
> 双索引对比——指标为符号边界准确率（macOS 上以 SourceKitten/SourceKit 输出
> 抽样校准）、Recall@K、引用准确率；tree-sitter 不显著胜出则不换，词法器留作
> 离线/解析失败降级路径（单文件回退并进 dead_letters）。
> Objective-C（`.h`/`.m` 双视图需归并同一符号 URN；消息发送 calls 规则不同）、
> Kotlin（top-level/companion/扩展函数）等新语言**待真语料出现时在 adapters
> 层按语言独立加适配器**，不在 S1 预先实现；core 届时抽出 `SymbolChunker` 协议
> 按文件后缀分发。

### FR-ING-003 质量评分与排序（P0，S1）
条目计算 quality_score（结构化程度、证据链接、完整度、后验证实），检索排序为
相关性 × 质量分 × 新鲜度衰减；烂数据只降权不删除。

- AC1：可解释单条得分构成；
- AC2：人工可配置权威等级权重。

### FR-ING-004 实体关系层 L1（P0，S2/S4）
抽取实体（需求/用例/符号/缺陷/文档章节/事故）与带 confidence+证据的关系；
低置信关系不面向用户展示、仅检索降权。

- AC1：用例↔符号、缺陷↔commit↔符号关系可在知识页浏览；
- AC2：每条关系可点开证据原文；
- AC3：抽检准确率纳入评测（目标 ≥0.85）。

### FR-KNO-001 混合检索（P0，S1）
FTS5(BM25) + Chroma 向量 + 融合/rerank；支持按项目/分支/密级/类型过滤；返回命中带版本与片段。

- AC1：记录向量-only / BM25-only / 混合各阶段命中率（评测可对比）；
- AC2：检索结果带 source URI 与 content_hash。

### FR-KNO-002 L3 规则资产（P1，S2）
术语表、prompt 模板、few-shot（提示词里附少量示例）、golden set（冻结的标准考题集）、
工具白名单（清单外调用一律拒绝）作为可版本化资产存储，改动留 diff。

## 4. 知识问答域（QA）

### FR-QA-001 问答工作流（P0，S1）
实现 07 §5.1 全图：意图/权限 → 检索 → 代码类强制 live-verify → 约束生成 → 引用校验 →
带标注回答 → 反馈采集。

- AC1：回答的每个事实性陈述带可点击引用；引用 URI 可达且 hash 与索引一致；
- AC2：引用校验失败时重生成一次；仍失败则输出"未知/证据不足"，不得给出无引用结论；
- AC3：答案标注文档版本与新鲜度（一致 ✅ / 验证于版本 X / 未知）。

### FR-QA-002 live-verify（现场核验，P0，S1）
代码类问题生成前实时读取 HEAD 代码复核引用符号存在性与函数体 hash；变更则当场重读重生成。

- AC1：构造"索引滞后于 HEAD"实验（改符号后未 reindex 直接问），答案仍以 HEAD 为准；
- AC2：应校验问题 100% 产生校验工具调用（trace 可查）。

### FR-QA-003 历史证词并列（P0，S1）
事故复盘类问题并列呈现"历史经验（日期/版本）"与"当前实现（HEAD 实时摘要）"，不混写、不改写原文。

- AC1：90s→30s 类陷阱题答案同时给历史值与当前值并各自标注。

### FR-QA-004 反馈采集（P0，S1）
每条回答可 👍/👎 + 原因分类（没召回/引用过期/答非所问/事实错）；反馈进入 bad case 池与偏好资产。

- AC1：反馈带 runId、问题、答案版本、模型版本落库；
- AC2：反馈率与分类在看板可见。

## 5. 测试设计域（TD）

### FR-TD-001 需求骨架抽取（P0，S2）
自由格式需求 → 骨架（固定四段结构）{功能点, 规则, 验收标准, 涉及模块}；验收标准缺失显式标缺，不编造。

- AC1：给定真实需求文档输出结构化骨架并列出缺口；
- AC2：结构化输出 100% 通过 schema 校验（结构合法率指标）。

### FR-TD-002 测试点生成（P0，S2）
基于需求 + 影响面检索（相似用例/事故/符号）生成测试点清单，每条带来源。

- AC1：支持专家盲标（专家先独立列清单封存，再揭示 AI 清单，防事后凑意见）评测流程（先录专家清单再揭示 AI 清单，自动算覆盖率/漏点/精确率）；
- AC2：P0/P1 级漏点与幻觉点在评测报告中单列。

### FR-TD-003 结构化用例与 oracle 挖掘（P0，S2）
生成 `{前置,步骤[],oracle[]}`，oracle 分 UI/日志/状态/人工四类；从需求验收标准、现有测试断言、
历史缺陷、当前代码四源挖 oracle，每条标注来源与置信度。

- AC1：对 V1 文档中 oracle_missing 用例，产出可采纳的 oracle 草稿或"探索性用例"标记；
- AC2：oracle 来源可追溯到断言行/需求条目/缺陷 ID；
- AC3：无法挖出可执行 oracle 的用例不进入自动化执行链路。

### FR-TD-004 用例草稿人审与回写（P0，S2）
草稿入审批队列；测试专家可采纳/修改/拒绝；批准后经 TestCaseRepositoryPort 回写（Markdown 适配器）；
人工修改 diff 存为偏好样本（quality +0.3 仅对 confirmed 条目）。

- AC1：未审批草稿不出现在正式用例库；
- AC2：回写是幂等（重复 N 次效果等于一次）的外部动作（走 outbox（外部写先在本地记账再派发），重放不重复写）。

## 6. 测试执行与失败归因域（EX）

### FR-EX-001 语言中立执行契约（P0，S3）
`TestExecutionRequest/TestRun/CaseResult` 模型字段不含 iOS 专有判断；scheme/udid 等仅存在于
xcode adapter 配置。

- AC1：同一份模型可被 xcode adapter 与离线 JUnit/Surefire 适配器各自产出合法 TestRun；
- AC2：准备一份 Surefire XML 通过契约测试（可在 S3 提前做，S5 验收）。

### FR-EX-002 独立 runner-worker（P0，S3）
执行请求经队列提交到独立 worker；支持排队、取消、超时、并发上限、每日重跑配额；
**orchestrator 进程不直接拉起 xcodebuild**。

- AC1：杀掉 worker 不影响 orchestrator；任务可在 worker 重启后被重新领取（幂等）；
- AC2：超时任务被终止并标 timeout；超过日配额的重跑被拒绝并记账；
- AC3：`-resultBundlePath` 已存在时先清理（03 §3 注意事项）。

### FR-EX-003 iOS 适配器（P0，S3）
hostless 测试（不起模拟器、不装 App 的纯逻辑测试，秒级）（`-only-testing:AlarmKitSpikeTests`）先通；XCUITest 单条选择执行后通；
命令参数化（workspace/scheme/destination udid）。

- AC1：真实跑通 hostless 套件并解析出用例级结果；
- AC2：至少一条真实 XCUITest 端到端跑通（慢，允许长超时）；
- AC3：模拟器操作遵守先 shutdown 再 erase、每用例干净启动（03 §3）。

### FR-EX-004 环境管理适配器（P0，S3）
EnvironmentPort：acquire（按能力标签选模拟器 udid）/health_check/reset/release；
能力不足显式返回 unsupported_capability。

- AC1：请求真机能力（后台音频/签名）在模拟器环境被拒绝并说明未覆盖层；
- AC2：租约泄漏有超时回收。

### FR-EX-005 报告与制品采集（P0，S3）
xcresulttool 解析测试结果树、失败信息；导出截图/录屏附件到 ArtifactStore（localfs），
返回带 hash/保留期的 URI；大文件不入向量库。

- AC1：失败用例可关联到其附件列表；
- AC2：录屏可抽帧（ffmpeg 脚本/说明）作为 UI 取证路径。

### FR-EX-006 日志查询适配器（P0，S3）
LogQueryPort 以 runId/时间窗/谓词查询 App 与系统侧 os_log（命令 03 §3.3–3.4），
查询谓词与时间窗本身计入证据。

- AC1：归因报告中每条日志证据可复现查询条件；
- AC2：只取时间窗内日志，不整量灌入知识库。

### FR-EX-007 失败归因（P0，S3）
对失败先列多候选（真缺陷/用例过期/flaky（同代码时过时不过的不稳定用例）/环境失败/产品改动），再以可区分实验取证：
flaky→配额内重跑验证；用例过期→比对断言期望与当前代码常量/行为；真缺陷→定位到符号与近期 diff。
输出结论 + 置信度 + 证据包 + 未覆盖层声明。

- AC1：用历史真实案例（90s→30s 期望过期、授权竞态、模拟器不暴露真机行为、flaky）各至少 1 例，
  归因与历史结论一致；
- AC2：输出混淆矩阵（各类 precision/recall），真缺陷 recall ≥0.95、误误导率 ≤0.02；
- AC3：**对照实验**（红证：故意改坏证明测试变红、还原变绿，证明测试真能抓 bug 而非假全绿）：临时回退一处修复/断言，相关用例与归因必须变红/改变，再恢复（留记录）；
- AC4：证据不足时输出"需人工判断"，不硬归因。

### FR-EX-008 CI 触发闭环（P1，S4）
PipelineFinished 事件 → 自动拉取结果 → 需要时发起选择重跑 → 归因 → 草稿，全程可在执行详情页追踪。

## 7. 写回、审批与外部副作用域（WR）

### FR-WR-001 HITL 审批（人在回路：机器只准备草稿、人点头才执行，P0，S2 起）
R0 只读/R1 内部草稿自动；R2（MR 评论、用例回写）默认审批；R3（建工单、工单流转、取消执行）
必须审批；R4（删数据/生产操作）禁止。动作分级配置化。

- AC1：每条 R2/R3 在 UI 可看到目标系统、请求体 diff、幂等键、回滚说明；
- AC2：审批人、时间、结论落库；存在一键停用开关（禁用所有外部写）。

### FR-WR-002 Outbox 与对账（P0，S3）
外部调用先持久化 OutboxRecord（发件箱账本：先记账再派发，中途被杀可幂等续；状态 pending/sent/confirmed/failed），再发起；
成功回写 external_ref；定时对账（账本与外部系统真实状态逐条比对）修复幻影记录（账本有、外部系统没有的中途态）。

- AC1：发起中途杀进程，重启后记录可幂等继续或被标记失败，不产生重复工单/评论；
- AC2：failed 记录可人工重试，重试沿用原幂等键。

### FR-WR-003 工单/评论写回（P0，S3）
归因经审批后在 JSON 工单系统建工单/加评论（含证据链接）；dry-run（空转：只记账本不真发外部写）模式默认开启。

- AC1：dry-run 只落 outbox 不调适配器写接口；
- AC2：写回内容含 runId、证据 URI、未覆盖层声明。

## 8. 保鲜与影响面域（FRS）

### FR-FRS-001 事件驱动增量摄入（P0，S4）
CommitPushed/MR/TestCaseUpdated/TicketClosed 等事件（04 §8 信封）触发增量 ETL；
定时全量扫描兜底；摄入延迟可观测。

- AC1：push 后 P95 <5 分钟对应变更可检索（用脚本事件实测）；
- AC2：事件可从 JSON 重放，重复投递幂等。

### FR-FRS-002 重构感知 stale/reindex（P0，S4）
知识锚定稳定 SymbolId；rename/move/签名变更经 git rename + AST diff 识别；
引用条目标 STALE（索引与当前代码对不上的过期标记）；高价值立即 reindex（重新切块嵌入替换旧索引），低价值 lazy；历史文档不改写只加版本注记。

- AC1：现场重命名 `schedulePrimary` → push（脚本事件）→ 条目变 STALE → 高价值条目 <10 分钟 reindex；
- AC2：再问同一问题，答案引用新符号名；事故文档原文未被修改；
- AC3：未标记的过期结果命中数 ≈0（06 §4 专项题集）。

### FR-FRS-003 影响面分析（P1，S4）
输入需求/分支/MR → 受影响代码符号 → 用例 → 历史缺陷；MR 摘要草稿（不依赖 message 质量，
从 diff 反推）。

- AC1：对一次真实变更给出影响用例清单并区分"无自动化/与 diff 冲突需更新"；
- AC2：推荐精度以实际执行结果回算（目标 ≥0.8）。

### FR-FRS-004 分支双轨（P2）
分支 namespace、blue-green 预索引——仅保留 branch 字段与接口，不实现。

## 9. 评测与可观测域（EV）

### FR-EV-001 golden set 管理（P0，S1）
题集文件版本化、与入库语料隔离（泄漏检查：题集引用的留出文档不在索引中）；
题型配比按 06 §6.1；支持盲标工作流数据结构。

- AC1：30 题（S1）→ 100 题（S5）；含 ≥15% 无答案负例；
- AC2：题集改动有评审记录（git 历史即可）。

### FR-EV-002 离线评测 worker（P0，S1）
一键跑评测：结构化断言（引用/hash/schema/分类标签）全自动 + RAGAS（RAG 评测框架，跑忠实度等语义指标）语义裁判（裁判模型与生成模型
不同体）+ 人工抽检录入；产出含数据/模型/prompt/参数版本四元组（四个版本号，任一变化结果不可直接对比）的报告，前后对比且降分也展示。

- AC1：同一冻结题集对两次配置跑出可对比报告；
- AC2：报告含召回侧/生成侧错误二分标签统计。

### FR-EV-003 POC 最小指标集（P0，S1–S4 分批）
自动采集 06 §7 的 10 指标：golden 通过率、引用准确率、Recall@K、忠实度、拒答正确率、
测试点覆盖/漏点、归因准确率/真缺陷 recall、采纳率/撤销率、单请求成本与延迟、摄入延迟。

- AC1：每个指标可追溯计算口径与原始记录；
- AC2：无基线的指标在看板标"无基线"，不展示百分比结论。

### FR-EV-004 trace 与日志（P0，S1）
Langfuse 记录每次检索、工具调用、模型调用、审批、成本；traceId 贯通 workflow→worker→TestRun；
结构化日志使用固定 logger/subsystem 名，文档给出抓取谓词。

- AC1：任一回答可从 UI 反查到完整 trace；trace 覆盖率 100%；
- AC2：worker（被系统拉起执行）不依赖 stdout 调试。

### FR-EV-005 在线反馈与 bad case 闭环（P1，S2 起）
反馈/bad case 台账、分诊状态、与 golden 增补、修复后回归关联；闭环周期可统计。

### FR-EV-006 护栏机器校验（P0，S3）
CI/评测中自动校验：无引用事实结论=0、白名单外工具调用=0、越权写=0、越层环境声称=0、幂等重复=0。

- AC1：任一护栏出现即评测失败。

## 14. 明确不做（当前范围）

- 不做通用聊天/开放问答；不做需求之外的多项目/多租户与组织权限体系；
- 不做模型训练/微调；不做 vLLM 推理优化与真机设备云（仅原理与 runbook 叙事）；

- 不为企业系统开发真实对接（GitLab/Jira 等），但 P2 位保留；
- 不把 AlarmKitSpike 源码拷入本仓。
